# XianWen 接口文档

- 状态：Draft v0.2
- 更新时间：2026-11-19
- 维护责任：A（核心规则）牵头，B（插件平台）、D（Web）、E（AI）共同 Review
- 关联文档：`docs/契约文档.md`、`docs/设计说明.md`、`docs/prd-v1.md`、`docs/tech-design-v1.md`

## 1. 文档目的

本文档定义模块之间可以依赖的公开接口、调用边界和写入权限。

接口文档回答：

1. Web、AI、插件和核心各自可以调用什么？
2. 哪些接口只产生提案，哪些接口可以提交状态？
3. 哪些内部实现不能被其它模块依赖？

字段定义、校验规则和版本约束见 `docs/契约文档.md`；设计原因和阶段划分见 `docs/设计说明.md`。

## 2. 分层与依赖方向

```text
Web
  → 核心公开查询与回合提交接口
  → 事件簿和公开状态投影

AI
  → 候选种子与公开世界投影
  → NarrativeDraft / ContentGenerationDraft / ForeshadowProposal
  → 不直接写状态

核心
  → 校验 AI 与插件提案
  → 登记生成内容
  → 应用 StandardEffect
  → 推进 CoreWorldState
  → 写入事件簿和伏笔账本

插件
  → 向 ContentRegistry 注册 SeedEvent、地点、人物、行动、结局和规则
  → 通过 StandardEffect 间接改变状态

Persistence
  → 保存 GameState、生成内容、事件簿、伏笔、插件状态和版本
```

明确禁止：

- Web 直接修改 `GameState` 或 `CoreWorldState`。
- AI 返回完整状态、年份、世界线阶段或已应用效果。
- 插件持有状态写引用。
- 普通叙事生成读取隐藏伏笔真相。
- 任何模块依赖另一个模块的私有实现。

## 3. 当前已实现接口（第一、二阶段）

当前代码位置：`src/xianwen/core/`。

### 3.1 核心公开函数

```python
new_game() -> LegacyGameState

get_current_event(state: LegacyGameState) -> Event

apply_choice(
    state: LegacyGameState,
    event_id: str,
    choice_id: str,
) -> TurnResult
```

当前行为：

| 接口 | 当前用途 | 限制 |
| --- | --- | --- |
| `new_game` | 创建第一阶段兼容状态 | 返回 LegacyGameState |
| `get_current_event` | 返回固定 `base.morning_training` | 仅接受 `LegacyGameState`；尚未实现新 `GameState` 候选筛选 |
| `apply_choice` | 校验固定事件和选项并返回 `TurnResult` | 尚未接入 AI、动态内容和生成效果 |

### 3.2 当前错误接口

```python
InvalidEventError  # 事件 ID 不可用
InvalidChoiceError  # 选项不属于当前事件
StateVersionConflictError  # 提交版本已经过期
InvalidStateTransitionError  # 迁移违反核心状态不变量
```

非法输入必须失败关闭，不能返回空结果，也不能修改输入状态。

### 3.3 世界状态分层与核心内部迁移接口（已实现）

以下接口属于核心内部/迁移期接口，不是插件公开 API。插件、AI 和 Web
只能提交 `StandardEffect` 等提案，不得构造 `StateTransition`，也不得
直接调用 `apply_state_transition()` 或 `advance_world()`。

插件可见 API 的隔离由后续 `feat/plugin-contract` 完成。在此之前，
即使这些符号可从 `xianwen.core` 导入，也不能作为插件调用入口。

```python
create_initial_world(
    *,
    world_seed: int = 0,
    worldline_id: str = "base.main",
    worldline_stage: str = "opening",
    content_version: str = "1.0",
) -> WorldSnapshot

build_state_transition(
    snapshot: WorldSnapshot,
    *,
    expected_version: int | None = None,
    new_dynamic: DynamicWorldState | None = None,
    advance_time: bool = False,
    applied_effects: tuple[StandardEffect, ...] = (),
    source: str = "core",
) -> StateTransition

apply_state_transition(
    snapshot: WorldSnapshot,
    transition: StateTransition,
) -> WorldSnapshot

advance_world(
    snapshot: WorldSnapshot,
    *,
    expected_version: int | None = None,
    new_dynamic: DynamicWorldState | None = None,
    applied_effects: tuple[StandardEffect, ...] = (),
    source: str = "core",
) -> WorldSnapshot
```

当前行为：

| 接口 | 当前用途 | 约束 |
| --- | --- | --- |
| `create_initial_world` | 创建第一回合世界快照 | 只初始化核心状态和空动态状态 |
| `build_state_transition` | 构造下一版状态请求 | 不修改传入快照 |
| `apply_state_transition` | 校验版本和核心字段并提交 | 只允许核心调用 |
| `advance_world` | 推进一个回合和一年 | 回合、年份和版本同步推进 |

提交规则：

- `expected_version` 必须等于当前快照的 `state_version`，否则抛出 `StateVersionConflictError`。
- `state_version` 每次提交必须精确增加 1。
- 普通提交不能修改 `world_seed`、`content_version` 或 `worldline_id`。
- `turn` 只能保持不变或增加 1；`year` 必须与 `turn` 同步变化。
- 世界线切换必须等待未来的专用迁移接口，不能走普通提交。
- Web、AI 和插件只能构造提案，不能直接调用 `apply_state_transition` 写入世界状态。

- `StateTransition.source` 只记录提案来源，不代表 plugin 或 AI 有权提交状态。

### 3.4 玩家与局状态（已实现）

```text
PlayerState
GameState(player, world, chronicle, foreshadows)
ChronicleEntry
ForeshadowBook
```

当前行为：

- `PlayerState` 保存玩家属性、声望、好感、物品、地点和标记。
- `GameState` 组合 `PlayerState` 与 `WorldSnapshot`，并提供事件簿和伏笔账本容器。
- `ChronicleEntry` 和 `ForeshadowBook` 目前只实现数据结构，尚未接入写入与调度逻辑。
- 旧 `new_game()` 返回 `LegacyGameState`，与新 `GameState` 暂时并行存在。

- `PlayerState` 只能由核心高层回合结算与世界状态一起原子更新。
- 插件、AI 和 Web 不得单独替换 `PlayerState` 或 `GameState`。
- 完整的 `PlayerState + WorldSnapshot` 原子提交接口由后续 `feat/seed-contract` 实现；同一回合必须返回一个完整 `GameState`。

### 3.5 当前兼容说明

当前 `Event` 和 `Choice` 是第一阶段固定可玩事件结构，不是最终 `SeedEvent`、`RenderedEvent` 或 `ContentGenerationDraft`。

当前 `GameState`、`apply_choice()` 和新 `WorldSnapshot` 并行存在。新接口可以逐步叠加，但必须保持当前最小回合在迁移期间可运行。

- `ChoiceEffect` 只用于旧 `LegacyGameState` 固定回合，不是插件新接口；新种子、插件和生成内容统一使用 `StandardEffect`。

### 3.6 Web HTTP 接口（第一阶段，已实现）

页面路由位于 `src/xianwen/web/routes.py`，第一版只调用旧核心兼容接口。

| 方法与路径 | 用途 | 成功 | 失败 |
| --- | --- | --- | --- |
| `GET /` | 开始页 | 200 HTML | - |
| `POST /game/start` | 创建新游戏并渲染第 1 年 | 200 HTML | - |
| `POST /game/choice` | 提交 `save`、`event_id`、`choice_id` | 200 HTML（结算 + 新状态） | 400 HTML（选项无效或存档损坏） |

约束：

- 页面状态只通过隐藏字段 `save`（`SaveDocument` JSON）在浏览器与路由之间流转，路由不保存会话状态。
- 路由不得直接构造或修改游戏状态，只能调用 `new_game`、`get_current_event`、`apply_choice`。
- 第一版 Web 路由仍使用 `LegacyGameState`；新 `GameState` 的 Web 对接在后续迁移中完成。
- 非法事件、非法选项和损坏存档必须失败关闭并返回明确错误，不能返回成功页面。
- 存档结构见 `docs/契约文档.md` 的 `SaveDocument`，禁止包含 API Key。

## 4. 目标公开接口（完整 MVP，尚未全部实现）

### 4.1 候选种子筛选

```python
select_candidate_seeds(
    snapshot: WorldSnapshot,
    registry: ContentRegistry,
    rng: RandomSource,
) -> tuple[SeedEvent, ...]
```

职责：

- 按年份、地点、事件分类、世界线阶段、条件、前序选择和伏笔到期筛选。
- 返回 2-3 个合格候选。
- AI 只能看到候选集，不能检索完整种子库。

随机性只能来自注入的 `RandomSource`，不得调用不可控全局随机。

### 4.2 叙事生成

```python
generate_narrative(
    candidates: tuple[SeedEvent, ...],
    public_context: PublicWorldProjection,
    request: ModelRequestConfig,
) -> NarrativeDraft
```

职责：

- 由 AI 层选择一个候选种子。
- 扩写场景、选项显示文字和结果文字。
- 不产生新规则效果或新选项 ID。

输出必须经 `validate_narrative_draft()` 校验后才能展示。

### 4.3 叙事草稿校验

```python
validate_narrative_draft(
    draft: NarrativeDraft,
    candidates: tuple[SeedEvent, ...],
) -> RenderedEvent
```

职责：

- 校验 `seed_id` 在候选集中。
- 校验 `choice_id`、数量和顺序与种子一致。
- 校验草稿不包含效果或状态字段。
- 合法时生成 `RenderedEvent`；非法时抛出明确错误，由调用方回退到后备文本。

### 4.4 受控内容生成

```python
generate_content(
    seed: SeedEvent,
    public_context: PublicWorldProjection,
    policy: ContentGenerationPolicy,
    request: ModelRequestConfig,
) -> ContentGenerationDraft
```

职责：

- 由 AI 层提出新地点、人物、事件、选项和效果草案。
- 所有 ID 只能是本次响应内的临时 ID。
- 不得直接引用未提供的私密状态或隐藏伏笔。
- 超出数量或效果预算时必须由后续校验拒绝。

### 4.5 生成内容校验

```python
validate_content_generation(
    draft: ContentGenerationDraft,
    snapshot: WorldSnapshot,
    policy: ContentGenerationPolicy,
) -> ValidatedGeneratedContent
```

职责：

- 校验内容和效果类型。
- 校验引用、命名空间、重复 ID 和数量预算。
- 校验数值范围、禁止效果和核心状态保护。
- 为地点、人物、事件和选项分配正式 ID。
- 输出可登记但尚未提交的已验证内容。

### 4.6 提交生成内容

```python
commit_generated_content(
    snapshot: WorldSnapshot,
    bundle: ValidatedGeneratedContent,
    expected_version: int,
) -> WorldSnapshot
```

职责：

- 以原子方式写入 `GeneratedContentStore`。
- 检查 `expected_version`，防止旧快照覆盖新快照。
- 生成新的不可变世界快照。
- 不得修改 `CoreWorldState` 的年份和世界线字段。

### 4.7 选择应用

```python
apply_choice(
    state: GameState,
    rendered_event: RenderedEvent,
    choice_id: str,
) -> TurnResult
```

职责：

- 从受信任的来源种子或生成事件中解析规则效果。
- 使用 `RenderedChoice.result_text` 展示已校验文本。
- 生成新的 `GameState` 和 `TurnResult`。
- 非法事件、选项或版本冲突必须抛出明确错误。

最终签名仍需在实现 AI 和事件簿前冻结。

### 4.8 事件簿写入

```python
append_chronicle_entry(
    state: GameState,
    event_id: str,
    choice_id: str,
    applied_effects: tuple[StandardEffect, ...],
    summary: str | None,
) -> GameState
```

职责：

- 保存选择事实和实际效果。
- 优先使用核心模板摘要。
- AI 摘要只能润色，不能改写事实。
- 更新涉及人物的 `CharacterMemory` 引用。

### 4.9 伏笔提案与评审

```python
propose_foreshadow(
    state: GameState,
    proposal: ForeshadowProposal,
) -> ForeshadowProposal

assess_foreshadow(
    proposal: ForeshadowProposal,
    public_context: PublicWorldProjection,
    request: ModelRequestConfig,
) -> ForeshadowAssessment

certify_foreshadow(
    proposal: ForeshadowProposal,
    assessment: ForeshadowAssessment,
    policy: ForeshadowPolicy,
    expected_version: int,
) -> GameState
```

职责：

- 提案和评分都是 AI 角色，但最终写入由核心完成。
- 认证前必须通过确定性校验。
- 认证后写入隐藏 `ForeshadowBook`。
- 超过阈值和活跃上限的伏笔必须拒绝。
- `due_turn` 不得超过来源回合加 10。

### 4.10 伏笔到期调度

```python
select_due_foreshadows(
    state: GameState,
    policy: ForeshadowPolicy,
) -> tuple[ForeshadowRecord, ...]
```

职责：

- 返回即将到期或已到期的认证伏笔。
- 核心优先选择带匹配 `payoff_tags` 的事件。
- 没有合适事件时触发核心后备回收事件。
- 未响应不得静默丢弃。

### 4.11 内容注册

```python
ContentRegistry
-register_base_content(...)  # 注册基础内容
-register_plugin(...)  # 校验并注册插件内容
-find_seed(seed_id)  # 按 ID 查找种子
-candidate_sources(...)  # 返回候选内容来源
-enabled_plugins  # 当前启用的插件元数据
```

约束：

- 发布前注册完成后冻结。
- 单个插件失败只禁用该插件。
- AI 生成内容不写入发布注册表，而写入当前局 `GeneratedContentStore`。
- 基础内容、插件内容和 AI 生成内容共用同一结构契约。

## 5. 权限矩阵

| 模块 | 读取核心状态 | 创建提案 | 应用效果 | 提交核心状态 | 写伏笔账本 |
| --- | --- | --- | --- | --- | --- |
| Web | 公开投影 | 否 | 否 | 否 | 否 |
| AI | 受限公开投影 | 是 | 否 | 否 | 否 |
| 插件 | 受限公开投影 | 是 | 仅标准效果 | 否 | 否 |
| 核心 | 是 | 可生成内部提案 | 是 | 是 | 是 |
| Persistence | 存档快照 | 否 | 否 | 仅保存 | 仅保存 |

## 6. 接口变更规则

- 新增或修改公开函数、类型、异常或协议：必须更新本文档。
- 修改返回类型、错误行为、调用顺序或写入权限：必须同步更新契约文档。
- 新增核心流程、模块边界或架构决策：必须更新设计说明。
- 接口变更必须补充测试，并在 PR 中列出调用方和迁移影响。
- 未同步文档的接口变更不得合并。
