# XianWen 接口文档

- 状态：Draft v0.1
- 更新时间：2026-11-18
- 维护责任：A（核心规则）牵头，B（插件平台）、D（Web）、E（AI）共同 Review
- 关联文档：`docs/契约文档.md`、`docs/设计说明.md`、`docs/prd-v1.md`、`docs/tech-design-v1.md`

## 1. 文档目的

本文档定义模块之间可以依赖的**公开接口**，以及不允许跨越的模块边界。

接口文档回答三个问题：

1. Web、插件和 AI 可以调用什么？
2. 各自可以传入什么、拿回什么？
3. 哪些内部实现不能被其他模块依赖？

本文档不定义具体内容细节；数据结构、校验规则和版本约束见 `docs/契约文档.md`，架构原因和阶段边界见 `docs/设计说明.md`。

## 2. 分层与依赖方向

目标依赖方向：

```text
Web 层
  → 应用/核心公开接口
  → 核心规则与状态迁移

插件层
  → 公开契约（SeedEvent / StandardEffect / ContentRegistry）
  → 核心只读取注册后的只读内容

AI 层
  → 候选种子与受限上下文
  → NarrativeDraft
  → 校验后再交给展示层

持久化层
  → GameState / 插件状态 / 存档版本契约
```

明确禁止：

- Web 直接修改 `GameState`。
- 插件直接修改 `GameState`。
- AI 返回数值、效果或完整状态。
- 核心依赖 FastAPI、Jinja2、浏览器存储或模型 SDK。
- 插件读取其他插件的私有状态。
- 任何模块依赖另一个模块的私有实现。

## 3. 当前已实现的接口（第一阶段）

当前代码位置：`src/xianwen/core/`

### 3.1 核心公开函数

```python
new_game() -> GameState

get_current_event(state: GameState) -> Event

apply_choice(
    state: GameState,
    event_id: str,
    choice_id: str,
) -> TurnResult
```

接口语义：

| 接口 | 输入 | 输出 | 当前行为 |
| --- | --- | --- | --- |
| `new_game` | 无 | `GameState` | 创建年份 1、修为 0、未结束的状态 |
| `get_current_event` | `GameState` | `Event` | 当前固定返回 `base.morning_training` |
| `apply_choice` | 状态、事件 ID、选项 ID | `TurnResult` | 校验后生成新状态并返回固定结果文本 |

### 3.2 当前错误接口

```python
InvalidEventError
InvalidChoiceError
```

规则：

- 事件 ID 不存在时抛出 `InvalidEventError`。
- 选项 ID 不属于当前事件时抛出 `InvalidChoiceError`。
- 非法输入不得静默返回空结果，也不得修改传入的状态。

### 3.3 当前消费者

| 消费者 | 允许依赖 | 不允许依赖 |
| --- | --- | --- |
| D / Web | `xianwen.core` 的公开导出 | `engine._resolve_*` 等私有函数 |
| B / 插件 | `Event`、`Choice`、`ChoiceEffect` 的公开形状 | 直接操作 `GameState` |
| E / AI | 当前回合的受限上下文与候选种子 | 直接修改状态或规则效果 |

当前 `Event` 是第一阶段固定可玩事件，不是最终 `SeedEvent`。详见契约文档。

## 4. 目标接口（草案，尚未实现）

以下接口用于完整 MVP，字段和签名需要在实现前由 A/B/D/E 共同冻结。

### 4.1 候选种子筛选

建议由核心提供：

```python
select_candidate_seeds(
    state: GameState,
    registry: ContentRegistry,
    rng: RandomSource,
) -> tuple[SeedEvent, ...]
```

职责：

- 按年份、地点、事件分类、世界线阶段和条件筛选。
- 返回 2-3 个合格候选。
- AI 不能跳过该筛选直接访问完整种子库。

随机性必须通过可注入随机源提供，不能直接依赖不可控全局随机。

### 4.2 叙事草稿校验

建议由 AI 层或共享校验层提供：

```python
validate_narrative_draft(
    draft: NarrativeDraft,
    candidates: tuple[SeedEvent, ...],
) -> RenderedEvent
```

职责：

- 校验 `seed_id` 确实属于候选集。
- 校验 `choice_id` 与原种子完全一致。
- 校验没有新增、删除或重排规则选项。
- 校验没有携带效果或状态修改。
- 合法时生成 `RenderedEvent`；非法时抛出明确错误，交由调用方回退到种子后备文本。

### 4.3 选择应用接口

完整 MVP 中，`apply_choice` 需要同时处理：

- 当前种子的规则效果。
- 玩家选择的选项 ID。
- 当前回合经过校验的展示文本。

因此最终签名尚未冻结，候选方案包括：

```python
apply_choice(
    state: GameState,
    turn: RenderedEvent,
    choice_id: str,
) -> TurnResult
```

无论最终采用哪种形式，必须满足：

1. 规则效果只能来自 `SeedEvent` 或核心认可的效果对象。
2. AI 生成的文本不能成为效果依据。
3. 非法选择必须抛出明确错误。
4. 返回新的 `GameState`，不得原地修改旧状态。

### 4.4 内容注册接口

建议由 B 的插件平台提供只读内容注册表：

```python
ContentRegistry
- register_base_content(...)
- register_plugin(...)
- find_seed(seed_id)
- candidate_sources(...)
- enabled_plugins
```

约束：

- 注册完成后冻结，运行期不允许任意增删。
- 插件加载失败时只移除该插件。
- 插件内容必须使用自己的 ID 命名空间。
- 核心只通过公开查询接口读取内容，不直接读取插件目录。

## 5. 接口变更规则

- 新增公开函数、类型、异常或协议：必须更新本文档。
- 修改函数签名、返回类型、异常行为或调用顺序：必须更新本文档和契约文档。
- 新增核心流程、模块边界或架构决策：必须更新设计说明。
- 接口变更必须同时补充对应测试，并在 PR 描述中列出调用方和迁移影响。
- 未同步文档的接口变更不得合并。

## 6. 待确认事项

这些事项在冻结前不得被实现成难以回退的公共契约。
