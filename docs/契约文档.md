- 状态：Draft v0.2
- 更新时间：2026-11-19
- 维护责任：A（核心规则）、B（插件平台）共同维护，D（Web）、E（AI）Review
- 关联文档：`docs/接口文档.md`、`docs/设计说明.md`、`docs/prd-v1.md`、`docs/tech-design-v1.md`

## 1. 文档目的

本文档定义跨模块共享的数据结构、字段含义、校验规则、状态不变量和版本约束。

接口文档描述“模块可以调用什么”，本文档描述“传进来的数据必须长什么样、哪些字段能改、什么情况下必须失败”。

本文档分为：

- 当前已实现契约：当前代码正在使用。
- 完整 MVP 契约：受控 AI 内容生成、事件簿和伏笔系统的目标契约，尚未全部实现。

未标注为“已实现”的结构都不得被当成当前代码事实。

## 2. 通用约定

### 2.1 ID 约定

所有稳定 ID 使用小写 ASCII 字符串：

```text
<namespace>.<name>
```

规则：

- `base.` 用于基础内容。
- 插件内容使用插件 ID 作为命名空间。
- AI 生成内容使用 `ai.<run-id>.<sequence>`，正式 ID 由核心分配。
- 事件 ID 全局唯一；选项 ID 在所属事件内唯一。
- 显示文本不能作为存档、AI 输出或插件引用的稳定标识。

### 2.2 不可变快照

`GameState`、`WorldSnapshot`、`CoreWorldState` 和 `DynamicWorldState` 均为不可变快照。

“动态世界状态”指它会随回合演化，不表示对象可以被原地修改。每次合法迁移都生成新版本。

### 2.3 单一权威来源

- 年份、回合、世界线和状态版本只存在于 `CoreWorldState`。
- 玩家属性和关系只存在于 `PlayerState` / `DynamicWorldState`。
- AI 生成内容和伏笔不得复制核心字段形成第二份权威来源。
- 所有状态提交必须带 `expected_version`，防止旧快照覆盖新快照。

### 2.4 JSON 与秘密

进入存档、HTTP 或模型输入输出的数据必须可序列化为 JSON。

禁止进入存档：

- API Key
- 真实模型凭据
- Python 函数对象
- 文件句柄或数据库连接
- 未脱敏的模型请求头

## 3. 状态契约

### 3.1 GameState（已实现）

`GameState` 是当前局的完整不可变快照，包含玩家状态、世界快照、事件簿和伏笔账本。

```text
GameState
- player: PlayerState                         # 玩家自身属性、关系、物品和标记
- world: WorldSnapshot                        # 当前世界快照
- chronicle: tuple[ChronicleEntry, ...]       # 已发生事件的结构化历史
- foreshadows: ForeshadowBook                 # 玩家不可见的伏笔账本
```

### 3.2 PlayerState（已实现）

`PlayerState` 保存玩家直接拥有的数值、关系、物品和叙事标签。

```text
PlayerState
- identity: str                               # 出身与身份
- realm: str                                  # 当前境界
- cultivation: int                            # 当前修为
- lifespan: int                               # 当前寿元
- injuries: int                               # 当前伤势
- mood: int                                   # 当前心境
- luck: int                                   # 气运值
- reputation: tuple[ReputationValue, ...]      # 各势力声望
- relationships: tuple[RelationshipValue, ...] # 关键人物好感
- items: tuple[ItemRecord, ...]                # 玩家持有物；不得与世界物品重复归属
- location_id: str | None                      # 当前地点
- flags: tuple[PlayerFlag, ...]                # 玩家标签和布尔标记
```

`PlayerState` 只能由核心高层回合结算更新，并且必须与 `WorldSnapshot`
在同一个 `expected_version` 提交中原子更新。插件、AI 和 Web 不得单独
提交或替换 `PlayerState`。

完整的高层原子提交接口由后续 `feat/seed-contract` 实现。

### 3.3 WorldSnapshot（已实现）

`WorldSnapshot` 是某一回合世界的不可变视图，分为核心权威状态和动态世界状态。

```text
WorldSnapshot
- core: CoreWorldState                        # 核心权威状态，只能由核心迁移
- dynamic: DynamicWorldState                  # 可演化内容，仍以不可变快照提交
```

### 3.4 CoreWorldState（已实现）

`CoreWorldState` 是世界权威状态，控制回合、年份、世界线和状态版本，任何 AI 或插件都不能直接修改。

```text
CoreWorldState
- turn: int                                   # 当前回合序号，从 1 开始
- year: int                                   # 当前年份，从 1 开始
- world_seed: int                             # 当前局随机种子
- worldline_id: str                           # 当前主线世界线 ID
- worldline_stage: str                        # 当前世界线阶段
- state_version: int                          # 单调递增的状态版本
- content_version: str                        # 当前内容与契约版本
```

不变量：

- `turn >= 1`
- `year >= 1`
- `state_version` 每次合法提交必须递增
- 年份推进必须通过核心的回合推进接口
- AI、插件和 Web 只能读取公开投影

### 3.5 DynamicWorldState（已实现）

`DynamicWorldState` 保存可以随游戏演化的世界内容，所有变化都必须通过核心校验。当前只实现最小记录字段，后续内容阶段再扩展。

```text
DynamicWorldState
- locations: tuple[LocationRecord, ...]       # 已发现或生成的地点
- characters: tuple[CharacterRecord, ...]     # 已出现或生成的人物
- relationships: tuple[RelationshipRecord, ...] # 玩家与人物、势力之间的关系
- factions: tuple[FactionRecord, ...]         # 势力和声望记录
- flags: tuple[WorldFlag, ...]                # 世界标记
- items: tuple[ItemRecord, ...]               # 世界关键、公共或掉落物品
- plugin_states: tuple[PluginStateRecord, ...] # 插件私有状态
- generated_content: GeneratedContentStore     # 当前局 AI 生成内容
```

当前已实现最小记录字段：

```text
LocationRecord
- id / name: str                              # 地点稳定 ID 和名称
- description: str                            # 地点描述

CharacterRecord
- id / name: str                              # 人物稳定 ID 和名称
- role / description: str                     # 人物身份和描述

RelationshipRecord
- source_id / target_id: str                  # 关系两端
- value: int                                  # 关系数值
- kind: str                                   # 关系类型

FactionRecord
- id / name: str                              # 势力稳定 ID 和名称
- description: str                            # 势力描述

WorldFlag
- key: str                                    # 世界标记键
- value: bool                                 # 标记值

ItemRecord
- id / name: str                              # 物品稳定 ID 和名称
- quantity: int                               # 数量，必须大于等于 1

PluginStateRecord
- plugin_id / key: str                        # 插件命名空间和私有状态键
- value: JsonScalar                           # JSON 标量状态
```

**物品归属规则：**

- `PlayerState.items` 保存玩家已经持有的物品。
- `DynamicWorldState.items` 保存世界中的关键物品、公共物品、掉落物和尚未被玩家取得的物品。
- 同一物品在同一时刻只能有一个权威归属，不得同时作为玩家持有物和世界物品独立存在。
- `AddItem`、`RemoveItem` 等标准效果必须声明目标归属；归属字段和完整效果白名单在 `StandardEffect` 冻结阶段确定。

### 3.6 StateTransition（已实现）

`StateTransition` 是核心提交一次状态变化的原子请求，不允许任何模块绕过它写入状态。

```text
StateTransition
- expected_version: int                       # 提交方看到的状态版本
- new_core: CoreWorldState                    # 核心生成的新核心状态
- new_dynamic: DynamicWorldState              # 核心生成的新动态状态
- applied_effects: tuple[StandardEffect, ...]  # 本次实际应用的效果
- source: str                                 # 提案来源标记；不代表外部模块有权提交状态
```

普通迁移必须满足：

- `expected_version` 等于提交方看到的状态版本。
- `new_core.state_version` 精确等于旧版本加 1。
- `world_seed`、`content_version` 和 `worldline_id` 不得变化。
- `turn` 只能不变或增加 1，`year` 必须同步变化。
- 世界线切换必须使用未来的专用迁移接口。

`source="plugin"` 或 `source="ai"` 只用于审计提案来源。插件和 AI 不得
构造或提交 `StateTransition`，该对象只能由核心内部创建和应用。

当前 `StateTransition` 只迁移 `WorldSnapshot`。完整 `GameState` 的高层
原子结算由 `feat/seed-contract` 实现：`PlayerState` 和 `WorldSnapshot`
必须在同一个版本提交中一起更新，插件不得单独替换玩家状态。

## 4. 种子内容契约

### 4.1 SeedEvent

`SeedEvent` 是由基础内容、插件或策划提供的规则与剧情骨架，AI 可以围绕它扩写或派生受控内容，但不能修改其规则后果。

```text
SeedEvent
- id: str                                     # 全局唯一事件 ID，基础内容使用 base. 命名空间
- category: str                               # 事件分类，例如 daily、combat、mystery
- worldline_id: str | None                    # 所属世界线；普通支线为空
- stage: str | None                           # 世界线阶段或事件阶段
- conditions: tuple[Condition, ...]           # 事件被选中前必须满足的条件
- weight: int                                 # 合格候选中的抽取权重，必须非负
- location_ids: tuple[str, ...]               # 允许触发该事件的地点 ID
- time_slots: tuple[str, ...]                 # 允许触发的时间段
- required_state: StateRequirement | None     # 额外状态门槛；为空表示无额外门槛
- fallback_scene_text: str                    # 无 AI 或 AI 失败时使用的完整场景
- ai_prompt: str                              # 给 AI 的额外叙事和生成提示
- narrative_brief: NarrativeBrief             # 结构化剧情简报，约束 AI 扩写空间
- choices: tuple[SeedChoice, ...]             # 2-4 个固定规则选项
- source_plugin_id: str | None                # 来源插件 ID；基础和 AI 生成内容可为空
```

### 4.2 SeedChoice

`SeedChoice` 是种子事件中的固定规则选项，定义规则效果和后备文本，AI 不得修改其 ID 和效果。

```text
SeedChoice
- id: str                                     # 事件内唯一选项 ID
- fallback_label: str                         # 无 AI 时显示的选项文字
- result_hint: str                            # 给 AI 的结果扩写提示
- fallback_result_text: str                   # 无 AI 时展示的结果文本
- effects: tuple[StandardEffect, ...]         # 由核心白名单校验并应用的效果
```

### 4.3 NarrativeBrief

`NarrativeBrief` 是种子事件提供给 AI 的结构化剧情简报，用来说明“可以扩写什么”和“不能改变什么”。

```text
NarrativeBrief
- premise: str                                # 本事件的核心情境和戏剧问题
- tone: str                                   # 叙事基调
- required_beats: tuple[str, ...]             # 扩写必须保留的剧情节点
- allowed_improvisation: tuple[str, ...]      # 允许 AI 自由发挥的临时细节
- forbidden_content: tuple[str, ...]          # 禁止 AI 引入的设定和规则变化
```

### 4.4 Condition

`Condition` 是一个可序列化的事件触发条件，用来判断当前世界是否满足条件。

```text
Condition
- kind: str                                   # 条件类型，例如 flag、relationship、item、year
- target: str                                 # 条件目标 ID 或状态字段名
- operator: str                               # 比较操作，例如 eq、neq、gte、lte、has
- value: str | int | bool                     # 比较值或目标值
```

`Condition` 的完整类型体系尚未冻结；当前实现不得擅自假定未登记的 kind。

### 4.5 StateRequirement

`StateRequirement` 是种子事件附加的状态门槛，和 `Condition` 一起参与候选筛选。

```text
StateRequirement
- min_year: int | None                        # 允许触发的最小年份
- max_year: int | None                        # 允许触发的最大年份
- min_cultivation: int | None                 # 最低修为
- max_cultivation: int | None                 # 最高修为
- required_flags: tuple[str, ...]             # 必须存在的标记
- forbidden_flags: tuple[str, ...]            # 必须不存在的标记
```

## 5. AI 内容契约

### 5.1 NarrativeDraft

`NarrativeDraft` 是 AI 返回的未校验叙事草稿，只能改场景、选项表达和结果文本。

```text
NarrativeDraft
- seed_id: str                                # AI 选中的候选种子 ID
- scene_text: str                             # 扩写后的场景文本
- choices: tuple[NarrativeChoice, ...]        # 与种子选项对应的展示文本
```

### 5.2 NarrativeChoice

`NarrativeChoice` 是 `NarrativeDraft` 中一个选项的展示文本，不携带规则效果。

```text
NarrativeChoice
- choice_id: str                              # 必须与种子中的 choice ID 完全一致
- display_text: str                           # 显示给玩家的选项文字
- result_text: str                            # 选择后展示的结果文字
```

### 5.3 ContentGenerationDraft

`ContentGenerationDraft` 是 AI 返回的未校验内容生成提案，允许提出新地点、人物、事件和选项，但不会直接进入世界状态。

```text
ContentGenerationDraft
- derived_from_seed_id: str                   # 本次生成依据的种子 ID
- locations: tuple[LocationDraft, ...]        # 新地点提案
- characters: tuple[CharacterDraft, ...]      # 新人物提案
- events: tuple[EventDraft, ...]              # 新事件提案
```

### 5.4 LocationDraft

`LocationDraft` 是 AI 提出的新地点草案，只有通过校验和正式 ID 分配后才能进入动态世界状态。

```text
LocationDraft
- local_id: str                               # 本次 AI 响应内的临时 ID
- name: str                                   # 地点名称
- description: str                            # 地点描述
- location_type: str                          # 地点类型，例如 sect、ruin、town
- tags: tuple[str, ...]                       # 用于筛选和叙事检索的标签
- connected_to: tuple[str, ...]               # 连接地点，可使用本地临时 ID
```

### 5.5 CharacterDraft

`CharacterDraft` 是 AI 提出的新人物草案，只有通过校验和正式 ID 分配后才能进入动态世界状态。

```text
CharacterDraft
- local_id: str                               # 本次 AI 响应内的临时 ID
- name: str                                   # 人物名称
- role: str                                   # 人物身份或叙事角色
- faction_id: str | None                      # 所属势力 ID
- description: str                            # 人物描述
- traits: tuple[str, ...]                     # 性格、能力和叙事标签
- relationship_hint: str | None               # 初始关系提示，不能直接改关系数值
```

### 5.6 EventDraft

`EventDraft` 是 AI 提出的新事件草案，可以派生自种子事件，但不能直接改变核心世界线。

```text
EventDraft
- local_id: str                               # 本次 AI 响应内的临时事件 ID
- derived_from_seed_id: str | None            # 派生来源种子 ID
- title: str                                  # 事件标题
- scene_text: str                             # 场景文本
- location_id: str | None                     # 发生地点，可使用本地临时 ID
- character_ids: tuple[str, ...]              # 涉及人物，可使用本地临时 ID
- choices: tuple[ChoiceDraft, ...]            # 新事件选项提案
```

### 5.7 ChoiceDraft

`ChoiceDraft` 是 AI 提出的新选项草案，效果必须经过白名单、引用和数值范围校验。

```text
ChoiceDraft
- local_id: str                               # 本次 AI 响应内的临时选项 ID
- label: str                                  # 选项显示文字
- result_text: str                            # 选项结果文本
- effects: tuple[EffectDraft, ...]            # 效果提案
```

### 5.8 EffectDraft

`EffectDraft` 是 AI 提出的标准效果草案，校验后才能转换为正式 `StandardEffect`。

```text
EffectDraft
- effect_type: str                            # 效果类型，例如 cultivation_delta、luck_delta
- target_id: str | None                       # 目标实体或字段 ID
- amount: int | None                          # 数值变化量
- value: bool | None                          # 标记类效果的目标值
```

## 6. 标准效果契约

### 6.1 StandardEffect

`StandardEffect` 是唯一允许修改游戏状态的受控效果联合类型，AI、插件和内容数据都只能提交效果，不能直接提交状态。

当前已实现一个只用于状态迁移审计的基础载体，包含 `effect_type`、`target_id`、`amount` 和 `value`。具体效果变体、白名单和数值边界仍待后续实现。

计划覆盖：

```text
CultivationDelta
- amount: int                                 # 修为变化，必须受范围限制

LuckDelta
- amount: int                                 # 气运变化，必须受范围限制

RelationshipDelta
- character_id: str                           # 关系目标人物
- amount: int                                 # 好感变化，必须受范围限制

ReputationDelta
- faction_id: str                             # 声望目标势力
- amount: int                                 # 声望变化，必须受范围限制

SetFlag / ClearFlag
- key: str                                    # 标记名称
- value: bool                                 # 设置或清除后的值

AddItem / RemoveItem
- item_id: str                                # 物品 ID
- quantity: int                               # 数量，必须为正整数

ChangeLocation
- location_id: str                            # 目标地点 ID

SetPluginState
- plugin_id: str                              # 插件命名空间
- key: str                                    # 私有状态键
- value: str | int | bool                     # JSON 可序列化值
```

硬性约束：

- 只允许白名单效果。
- 目标必须存在且属于允许的作用域。
- 数值不得超过 `ContentGenerationPolicy`。
- 死亡、突破和最终结局不能作为普通插件或 AI 效果直接写入。
- 超限必须拒绝，不能静默裁剪。

### 6.2 ContentGenerationPolicy

`ContentGenerationPolicy` 定义 AI 内容生成和效果提交的数量、类型和数值边界。

```text
ContentGenerationPolicy
- max_locations_per_turn: int                 # 每回合最多新增地点数
- max_characters_per_turn: int                # 每回合最多新增人物数
- max_events_per_turn: int                    # 每回合最多新增事件数
- max_options_per_event: int                  # 单个事件最多选项数
- max_effects_per_choice: int                 # 单个选项最多效果数
- allowed_effect_types: tuple[str, ...]       # 允许的标准效果类型
- effect_bounds: tuple[EffectBound, ...]      # 每种效果的数值上下限
- max_total_effect_per_turn: int              # 单回合总效果预算
- forbidden_effect_types: tuple[str, ...]     # 明确禁止的效果
- max_active_foreshadows: int                 # 同时存在的认证伏笔上限
- max_model_calls_per_turn: int               # 单回合模型调用上限
```

## 7. 展示与回合结果契约

### 7.1 RenderedEvent

`RenderedEvent` 是经过校验、可以直接展示给玩家的当前回合事件，不携带可修改规则的效果。

```text
RenderedEvent
- seed_id: str                                # 来源种子或生成事件 ID
- scene_text: str                             # 已校验的场景文本
- choices: tuple[RenderedChoice, ...]         # 已校验的展示选项
```

### 7.2 RenderedChoice

`RenderedChoice` 是玩家在当前回合看到的一个已校验选项，规则效果仍由核心从种子或生成事件定义中解析。

```text
RenderedChoice
- choice_id: str                              # 稳定选项 ID
- display_text: str                           # 显示文字
- result_text: str                            # 选择后展示的结果文本
```

### 7.3 TurnResult

`TurnResult` 是一次选择完成后的结果快照，包含新状态、实际选项和展示结果。

```text
TurnResult
- state: GameState                            # 新生成的状态快照
- event_id: str                               # 实际执行的事件 ID
- choice_id: str                              # 实际执行的选项 ID
- result_text: str                            # 展示给玩家的结果文本
```

## 8. 生成内容与事件簿契约

### 8.1 GeneratedContentStore（已实现）

`GeneratedContentStore` 保存当前局 AI 生成并校验通过的地点、人物和事件，必须随存档恢复。当前实现使用统一的 `GeneratedContentRecord` 元数据载体。

```text
GeneratedContentStore
- locations: tuple[GeneratedContentRecord, ...]   # 已登记地点
- characters: tuple[GeneratedContentRecord, ...]  # 已登记人物
- events: tuple[GeneratedContentRecord, ...]      # 已登记事件
```

### 8.2 GeneratedContentRecord（已实现）

`GeneratedContentRecord` 是 AI 生成内容的来源和版本元数据，用于追溯、存档和兼容迁移。

```text
GeneratedContentRecord
- id: str                                     # 核心分配的正式 ID
- kind: str                                   # location、character 或 event
- source_seed_id: str | None                  # 来源种子 ID
```

## 9. 伏笔契约

### 9.1 ForeshadowProposal

`ForeshadowProposal` 是 AI 提出的未认证伏笔候选，必须经确定性校验和第二个评审 agent 评分。

```text
ForeshadowProposal

- stakes: str                                 # 回收后的风险或收益
```

### 9.2 ForeshadowAssessment（结构已实现）

`ForeshadowAssessment` 是第二个评审 agent 对伏笔候选的结构化评分，不直接写入世界状态。

```text
ForeshadowAssessment
- world_consistency: int                      # 0-100，世界观一致性
- causal_clarity: int                         # 0-100，因果清晰度
- payoff_feasibility: int                     # 0-100，未来回收可行性
- narrative_value: int                        # 0-100，叙事价值
- spoiler_risk: int                           # 0-100，提前泄露风险
- total_score: int                            # 0-100，综合评分
- recommendation: str                         # accept、revise 或 reject
- reason: str                                 # 评分理由
```

### 9.3 ForeshadowRecord（结构已实现）

`ForeshadowRecord` 是认证后的隐藏伏笔事实，玩家不可见，由核心负责到期调度和响应。

```text
ForeshadowRecord
- id: str                                     # 伏笔记录 ID
- source_event_id: str                        # 来源事件 ID
- source_turn: int                            # 提出伏笔的回合
- content: str                                # 隐藏事实
- payoff_tags: tuple[str, ...]                # 回收匹配标签
- due_turn: int                               # 最晚响应回合，不得超过来源回合加 10
- status: str                                 # certified、due、resolved 或 expired
- assessment: ForeshadowAssessment             # 认证评分记录
```

### 9.4 ForeshadowBook（结构已实现）

`ForeshadowBook` 是当前局所有伏笔候选、认证记录和到期状态的隐藏账本。

```text
ForeshadowBook
- records: tuple[ForeshadowRecord, ...]       # 已认证和历史伏笔
- max_active: int                             # 最大活跃伏笔数量
```

认证规则：

1. 确定性校验必须通过。
2. 评分总分和关键维度必须超过阈值。
3. 超过活跃伏笔上限时拒绝或要求先回收。
4. 到期前核心必须调度响应；无可用事件时触发后备回收事件。
5. 未响应不得静默丢弃，必须产生明确后果。

## 10. 跨模块硬性不变量

1. 代码是世界事实和规则后果的唯一权威。
2. AI 可以生成叙事和结构化内容提案，但不得直接修改状态。
3. 插件只能提交标准效果，不能直接修改 `GameState` 或 `CoreWorldState`。
4. 年份、回合、世界线阶段和状态版本只能由核心推进。
5. AI 生成内容必须经过校验、正式 ID 分配、登记和存档。
6. 事件簿摘要不能改写已应用的选择和效果事实。
7. 伏笔必须经过确定性校验和评审阈值认证，并由核心在十回合内调度。
8. 普通叙事生成不能读取隐藏伏笔真相。
9. 所有 AI 和插件数据必须失败关闭，不能静默接受非法字段。
10. 后备模式下不产生新的 AI 生成内容，但基础游戏必须可继续。

## 11. 版本与兼容

- 插件清单必须包含 `api_version`。
- AI 生成内容和存档必须记录 `content_version`、生成器版本和来源种子。
- 契约发生不兼容变化时提升接口版本或存档版本。
- 存档必须记录启用插件 ID、版本、插件私有状态、生成内容和伏笔记录。
- 新增字段优先采用向后兼容的可选字段；删除字段或不兼容语义变化必须走迁移。
- 契约变更必须同步更新本文档、接口文档、设计说明和测试。
