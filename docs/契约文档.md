- 状态：Draft v0.1
- 更新时间：2026-11-18
- 维护责任：A（核心规则）、B（插件平台）共同维护，D（Web）、E（AI）Review
- 关联文档：`docs/接口文档.md`、`docs/设计说明.md`、`docs/prd-v1.md`、`docs/tech-design-v1.md`

## 1. 文档目的

本文档定义跨模块共享的**数据结构、校验规则、状态不变量和版本约束**。

接口文档描述“模块可以调用什么”，本文档描述“传进来的数据必须长什么样、什么情况下必须失败”。

本文档分为两部分：

- 第一阶段已实现契约：当前代码正在使用的契约。
- 完整 MVP 目标契约：已从 PRD 提炼、但尚未实现的草案。

未经明确标注，目标契约不应被当成已实现功能。

## 2. 通用约定

### 2.1 ID 约定

所有稳定 ID 使用小写 ASCII 字符串：

```text
<namespace>.<name>
```

示例：

```text
base.morning_training
official-example.ancient_ruins
```

规则：

- `id` 是机器契约，不是显示文本。
- 显示文本放在 `label`、`scene_text`、`result_text` 等字段。
- 基础内容使用 `base.` 命名空间。
- 插件事件必须使用自身插件 ID 作为命名空间。
- 事件 ID 全局唯一；选项 ID 在所属事件内唯一。
- 存档、AI 输出和插件数据只能引用稳定 ID，不能引用显示文本。

### 2.2 JSON 可序列化

所有进入存档、跨 HTTP 边界或进入插件状态的契约字段必须可序列化为 JSON。

不能序列化：

- Python 函数对象
- 任意类实例
- 文件句柄
- 数据库连接
- API Key 或其他秘密

### 2.3 不可变性

核心状态和内容注册表使用不可变或复制后替换的策略。

- `GameState` 不得被 Web 或插件原地修改。
- `SeedEvent` 和 `RenderedEvent` 的 ID 与规则字段不得被 AI 修改。
- 注册表加载完成后冻结。

## 3. 第一阶段已实现契约

### 3.1 GameState

```text
GameState
- year: int = 1
- cultivation: int = 0
- ended: bool = false
```

不变量：

- `year >= 1`
- `cultivation >= 0`
- `ended` 是布尔值
- 当前阶段只允许通过核心引擎生成新状态

这是第一阶段最小状态，不是完整角色状态。完整状态字段尚未锁定。

### 3.2 ChoiceEffect

```text
ChoiceEffect
- cultivation_delta: int = 0
```

当前只支持修为变化，是完整 `StandardEffect` 模型的过渡占位。

约束：

- 插件只能提交效果，不能修改 `GameState`。
- 年份推进由核心统一执行，不放入插件效果。
- 非法效果或未知效果必须拒绝。

### 3.3 Choice

```text
Choice
- id: str
- label: str
- result_text: str
- effect: ChoiceEffect
```

字段语义：

- `id`：稳定选项 ID，AI 不得修改。
- `label`：显示给玩家的文字。
- `result_text`：玩家选择后展示的固定后备结果文字。
- `effect`：由核心应用的标准效果。

### 3.4 Event

```text
Event
- id: str
- scene_text: str
- choices: tuple[Choice, ...]
```

当前 `Event` 是第一阶段固定可玩事件的完整文本结构，**不是完整 `SeedEvent`**。

缺少的完整种子能力包括：

- 事件分类
- 世界线与阶段
- 触发条件
- 权重
- 地点和时间要求
- AI 扩写提示
- 多类型标准效果
- 插件来源信息

### 3.5 TurnResult

```text
TurnResult
- state: GameState
- event_id: str
- choice_id: str
- result_text: str
```

约束：

- `state` 必须是新的不可变状态快照。
- `event_id` 和 `choice_id` 必须来自实际执行的规则内容。
- `result_text` 在 AI 模式下可以来自通过校验的叙事草稿；不能反过来影响规则效果。

## 4. 完整 MVP 目标契约（草案）

### 4.1 SeedEvent

完整种子事件是规则和内容的真实来源：

```text
SeedEvent
- id: str
- category: str
- worldline_id: str | None
- stage: str | None
- conditions: tuple[Condition, ...]
- weight: int
- location_ids: tuple[str, ...]
- time_slots: tuple[str, ...]
- required_state: StateRequirement | None
- fallback_scene_text: str
- ai_prompt: str
- choices: tuple[SeedChoice, ...]
- source_plugin_id: str | None
```

要求：

- 事件本身必须是完整可玩的最小事件。
- 每个事件提供 2-4 个固定选项。
- 每个事件和每个选项结果都有后备文本。
- AI 扩写提示不能改变规则语义。
- 基础内容和插件内容使用同一注册/筛选口径。

### 4.2 SeedChoice

```text
SeedChoice
- id: str
- fallback_label: str
- fallback_result_text: str
- effects: tuple[StandardEffect, ...]
```

约束：

- `id` 是玩家选择与规则效果的唯一连接点。
- AI 只能改 `fallback_label` 和 `fallback_result_text`，不能改 `id` 或 `effects`。
- `effects` 由核心校验并应用。

### 4.3 NarrativeDraft

AI 的唯一常规输出：

```text
NarrativeDraft
- seed_id: str
- scene_text: str
- choices: tuple[NarrativeChoice, ...]

NarrativeChoice
- choice_id: str
- display_text: str
- result_text: str
```

禁止字段：

- 新选项
- 新 choice ID
- 数值变化
- 状态变化
- 新地点、人物、物品或结局条件
- 死亡、突破、结局判定

校验失败时：

1. 允许重试一次。
2. 重试仍失败则丢弃 AI 文本。
3. 使用 `SeedEvent` 和 `SeedChoice` 的后备文本。

### 4.4 RenderedEvent

当前回合展示给玩家的已校验内容：

```text
RenderedEvent
- seed_id: str
- scene_text: str
- choices: tuple[RenderedChoice, ...]

RenderedChoice
- choice_id: str
- display_text: str
- result_text: str
```

`RenderedEvent` 不携带可修改规则的效果。核心应用选择时仍必须回到 `SeedEvent` 或受信任的回合上下文解析效果。

### 4.5 StandardEffect

完整 MVP 的标准效果是受控的可辨识联合类型。当前计划覆盖：

```text
CultivationDelta
ReputationDelta
SetFlag / ClearFlag
AddItem / RemoveItem
ChangeLocation
SetPluginState
```

统一约束：

- 插件和声明式内容只能提交效果，不能提交状态对象。
- 核心只应用白名单效果。
- 未知效果、越界数值和非法目标必须拒绝。
- 死亡、突破和最终结局不能作为普通插件效果直接写入。
- 所有效果必须可测试、可序列化、可审计。

### 4.6 ContentRegistry

注册表是基础内容和已启用插件内容的统一只读视图：

```text
ContentRegistry
- base seeds
- plugin seeds
- locations
- characters
- actions
- endings
- plugin rules
- enabled plugin metadata
```

约束：

- 注册前完成清单、字段、命名空间和重复 ID 校验。
- 注册完成后冻结。
- 单个插件失败只禁用该插件。
- 插件被禁用时保留其历史私有状态，避免重新启用后丢档。
- 核心只读取注册表，不直接扫描/执行插件目录。

### 4.7 插件清单

最小 `plugin.toml`：

```toml
id = "official-example"
name = "Official Example"
version = "0.1.0"
api_version = "1"
```

完整插件包可按能力提供：

```text
plugins/<plugin-id>/
├── plugin.toml
├── content/
│   ├── locations.toml
│   ├── characters.toml
│   ├── events.toml
│   └── endings.toml
└── rules.py        # 可选
```

第一阶段只要求纯数据插件，不要求 `rules.py`。

## 5. 跨模块硬性不变量

1. 游戏逻辑在代码里，LLM 只生成叙事文本。
2. AI 不得修改数值、状态、选项 ID、选项数量、规则效果、死亡、突破或结局。
3. 插件不得直接修改 `GameState`，只能提交标准效果。
4. 核心是唯一允许创建新游戏状态和判定核心结果的模块。
5. 所有事件和结果必须有后备文本，AI 不可用时仍可玩。
6. 所有插件私有状态必须 JSON 可序列化，并按插件命名空间隔离。
7. 所有稳定 ID 必须可跨存档、HTTP、AI 输出和插件内容保持一致。
8. 任何无法校验的 AI 或插件数据都必须失败关闭，不能静默接受。

## 6. 版本与兼容

- 插件清单必须包含 `api_version`。
- 契约发生不兼容变化时提升 `api_version`。
- 存档必须记录启用插件 ID、版本和插件私有状态。
- 新增字段优先采用向后兼容的可选字段；删除字段或不兼容语义变化必须走版本迁移。
- 契约变更必须同步更新本文档、接口文档和对应测试。

## 7. 待冻结事项

以下内容仍待 A/B/D/E 共同确认：

- 完整 `GameState` 字段与插件新增属性的映射方式。
- `Condition`、`StateRequirement` 的声明式格式。
- `StandardEffect` 的精确字段和数值边界。
- `rules.py` 的公开钩子签名。
- 插件规则与核心结算的异常隔离方式。
- AI 草稿校验器的归属模块。
