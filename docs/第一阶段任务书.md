## 1. 阶段目标

第一阶段不制作完整游戏，只完成一个极小但真实可运行、可测试、可扩展的回合：

```text
打开页面
→ 点击“开始游戏”
→ 看到一个固定事件
→ 选择“修炼”或“休息”
→ 核心规则修改状态
→ 年份从第 1 年推进到第 2 年
→ 页面显示新的年份和修为
```

完成这个闭环后，再从真实代码中固化第一版核心、Web、存档和插件契约。不得先设计一套没有运行路径验证的复杂接口。

## 2. 第一阶段最小规格

### 2.1 最小游戏状态

第一阶段只要求以下字段：

```text
GameState
- year: int               当前年份，初始为 1
- cultivation: int        修为，初始为 0
- ended: bool             是否结束，初始为 false
```

暂时不要加入声望、伤势、人物关系和完整世界线字段。后续确有用例时再通过独立改动增加。

### 2.2 最小基础事件

```text
事件 ID：base.morning_training
场景：清晨灵气尚可，你准备如何度过今日？

选项 cultivate：修炼
- cultivation +1
- year +1

选项 rest：休息
- cultivation 不变
- year +1
```

两个选项都必须提供固定场景文本和固定结果文本，不依赖 AI。

### 2.3 最小核心接口

第一阶段只实现以下三个核心操作：

```python
new_game() -> GameState

get_current_event(state: GameState) -> Event

apply_choice(
    state: GameState,
    event_id: str,
    choice_id: str,
) -> TurnResult
```

具体类型以实际代码为准，但必须满足：

- Web 层不能直接修改 `GameState`。
- 插件只能提供事件和标准效果，不能直接修改 `GameState`。
- 非法事件或选项返回明确错误，不能静默忽略。
- 相同输入必须得到可重复测试的结果。

## 5. B：田梦婷——插件平台负责人

### 5.1 今日目标

根据 A 已经运行的事件模型设计最小插件格式，不提前设计完整插件系统。

### 5.2 建议文件

第一天先完成文档和数据样例；A 的最小核心合并后再实现加载器。

```text

src/xianwen/plugins/
├── __init__.py
├── models.py
├── loader.py
└── registry.py

tests/unit/
└── test_plugin_loader.py
```

### 5.3 今日具体任务

1. 阅读 A 的 `Event`、`Choice` 和效果表示。
2. 在 `docs/plugin-spec.md` 定义最小 `plugin.toml`：
   - `id`
   - `name`
   - `version`
   - `api_version`
3. 定义插件事件数据格式：
   - 事件 ID 和命名空间
   - 固定场景文本
   - 2～4 个选项
   - 每个选项的标准效果
   - 每个选项的固定结果文本
4. 定义第一阶段只支持的标准效果，例如修为变化；不要一次设计全部正式效果。
5. 定义以下失败行为：
   - 缺少必填字段时拒绝插件。
   - 缺少固定后备文本时拒绝插件。
   - ID 不属于插件命名空间时拒绝插件。
   - 单个插件加载失败时保留基础事件，并返回明确错误。
6. 与 C 核对文档是否足以制作一个插件目录。

### 5.4 A 合并后的实现任务

实现最小加载流程：

```text
读取 plugin.toml
→ 读取 events.toml
→ 校验字段和命名空间
→ 转换成核心 Event
→ 注册到事件列表
```

第一阶段不实现 `rules.py`，只支持纯数据插件。

### 5.5 必写测试

- 合法插件能够加载并注册一个事件。
- 缺少 `fallback_text` 时加载失败。
- 缺少选项结果文本时加载失败。
- 插件事件 ID 不属于自身命名空间时加载失败。
- 一个插件加载失败后，基础事件仍然存在并可使用。

### 5.6 今日交付

- 建议分支：`docs/plugin-contract-v1`
- 建议提交：`docs: define minimal plugin contract`
- 第一份 PR 只包含契约和示例；加载器可在 A 合并后单独提交。
- 主要审查人：A、C。

### 5.7 完成标准

- C 不阅读插件加载器内部代码也能写出正确目录。
- 插件事件可以转换为核心的公开 `Event`，无需修改核心源码。
- 插件不能直接获得或修改 `GameState`。
