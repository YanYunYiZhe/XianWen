# XianWen MVP 产品需求文档

- 状态：Draft v1.1
- 更新时间：2026-11-18
- 本版变更：采用受控 AI 内容生成、核心/动态世界状态分层、事件簿和隐藏伏笔系统

## 1. 产品概述

XianWen 是一款单人中文修仙文字游戏。玩家在云州扮演一名散修，以每回合一年的节奏经历 10 年修行人生。世界会持续变化，玩家可以选择介入或回避；规则保存世界事实，AI 在受限契约内扩写叙事并生成新的地点、人物、事件、选项和伏笔提案。

MVP 的核心承诺更新为：

> 代码是世界事实和规则后果的唯一权威；AI 是受约束的内容生成层，所有生成内容必须经过校验、登记并随存档保存。

## 2. MVP 目标

玩家应能在浏览器中完成一局约 10-15 分钟的游戏，并清楚感受到：

1. 自己的选择会改变人物、关系和世界线。
2. 被忽略的事件也会继续发展。
3. 早期选择会在数回合后产生后续影响。
4. 没有 AI 服务时，游戏仍能完整游玩。
5. AI 生成的地点、人物、事件和选项持续存在于当前世界，而不是刷新后消失。
6. 已认证伏笔会在十回合内得到响应，不能静默失效。
7. 不负责核心模块的组员可以依靠公开文档和示例扩展游戏内容与规则。

## 3. MVP 范围

### 包含

- 10 个年度回合，每回合代表一年。
- 单机、中文、浏览器本地运行；公网访问为课程后可选增强。
- 玩家不能自由输入行动，只能在 2-4 个已校验选项中选择。
- 核心世界状态与动态世界状态分离，所有状态以不可变快照提交。
- 种子事件库、世界线推进、事件簿和人物记忆。
- AI 叙事扩写和受控内容生成。
- AI 可提出新地点、新人物、新事件、新选项和受限标准效果。
- 事件簿记录每次事件和玩家选择的一到两句摘要。
- 隐藏伏笔的提案、评分、认证、保存和十回合内响应。
- 无 AI 时的固定文本后备模式。
- 课程 MVP 只启用一个主模型预设，用户自带 API Key。
- 插件审核后随应用发布。
- 一个官方示例扩展包，同时作为组内独立扩展课程验收包。

### 不包含

- 账号系统、云存档和跨设备同步。
- 多人游戏。
- 自由文字行动。
- 复杂回合制战斗。
- 超大世界地图。
- 图片、音频或视频生成。
- 插件上传市场、评分系统或在线审核后台。
- 月程、逐日行动和精细日程模拟。
- AI 直接创建新的主线世界线或最终结局。
- AI 直接修改死亡、突破、年份、世界线阶段或核心世界状态。
- 第二、第三个模型预设的课程验收。
- 团队外部作者参与课程验收。

### 课程交付硬性范围

课程验收以以下内容为硬性门槛：

1. 一个完整的 10 回合单局流程，可从新游戏走到结局并重新开始。
2. 一个主模型预设加固定后备文本；测试和本地演示不依赖真实模型网络。
3. 核心世界状态与动态世界状态分层，AI 和插件无法直接修改核心权威字段。
4. 一条受控 AI 内容生成路径：至少生成一个新地点、一个新人物、一个新事件和一个新选项，并随存档恢复。
5. 事件簿至少记录每回合事件、玩家选择、结构化效果和一到两句摘要。
6. 一套伏笔流程：提案、评分、阈值认证、隐藏保存，并在一到十回合内得到响应。
7. 一个由不负责核心模块的组员独立完成的扩展包，可启用、禁用、故障隔离并随存档恢复。
8. 正常、边界/失败和扩展契约测试；一次故意引入错误并确认测试失败的演示。
9. GitHub Actions 至少一次真实成功 CI，执行构建、测试和基础静态检查。
10. 五人均有代码或测试贡献、至少一次具体 Review，并使用 Tag、发行 ZIP 和 `release/RELEASE.md` 完成可追溯发布。
11. `README.md`、`LICENSE`、`docs/DESIGN.docx` 和组内扩展接入说明齐全。

### 课程后延期项

- 公网部署、CD、部署 Webhook 和公开 URL 健康检查。
- 除主预设外的第二、第三个模型适配。
- 团队外部作者、插件市场、热加载和社区运营。
- 20 回合、第三结局、第三世界线和移动端精细适配。

## 4. 核心循环

每回合按以下顺序执行：

1. 核心从 `CoreWorldState` 和当前世界快照中筛选 2-3 个合格种子事件。
2. AI 在候选中选择种子，并返回叙事草稿和可选的内容生成提案。
3. 核心校验叙事草稿、生成内容、ID、引用、数量和标准效果预算。
4. 合法内容被分配正式 ID，写入当前局的 `GeneratedContentStore`。
5. 合法叙事被转换为 `RenderedEvent`；失败时使用种子后备文本。
6. 玩家在 2-4 个已校验选项中选择。
7. 核心依据种子或生成事件的规则效果生成新的世界快照。
8. 核心写入结构化事件簿记录；AI 可生成一到两句摘要，失败时使用固定摘要。
9. 伏笔提案经过确定性校验和第二个评审 agent 打分；超过阈值后进入隐藏 `ForeshadowBook`。
10. 核心检查到期伏笔，并保证其在十回合内得到响应；随后推进年份和世界线。

AI 可以承担多个受控角色：叙事扩写、内容生成提案、伏笔评审和事件摘要。每个角色的调用都必须计入单局模型预算，不能直接修改状态。

### 回合约束

- 玩家不能自由输入行动。
- 每个事件至少有一个带代价的退路，例如暂避、离开、保守处理或付出资源。
- 任何场景都不能出现没有可继续操作的死局。
- 失败必须产生具体后果，不能出现“什么也没发生”的结果。
- AI 不能决定死亡、突破成功或最终结局。
- AI 生成的效果必须满足类型白名单、目标存在性和数值范围。
- 单个事件中新增地点、人物和事件的数量受 `ContentGenerationPolicy` 限制。

## 5. 状态模型

### 5.1 GameState

`GameState` 是当前局的完整不可变快照，所有模块只能读取它，只有核心可以生成下一版。

```text
GameState
- player: PlayerState              # 玩家自身属性、关系、物品和标记
- world: WorldSnapshot             # 世界状态快照，包含核心状态和动态状态
- chronicle: tuple[ChronicleEntry, ...]  # 已发生事件的结构化记录和摘要
- foreshadows: ForeshadowBook      # 玩家不可见的伏笔账本
```

### 5.2 WorldSnapshot

`WorldSnapshot` 是某一回合的世界不可变快照，分为核心权威部分和动态部分。

```text
WorldSnapshot
- core: CoreWorldState             # 只能由核心规则推进的权威状态
- dynamic: DynamicWorldState       # 记录生成内容、人物、地点、关系和插件状态
```

### 5.3 CoreWorldState

`CoreWorldState` 是世界权威状态，AI、插件和 Web 都不能直接修改；年份、回合和世界线只能通过核心的状态迁移函数推进。

```text
CoreWorldState
- turn: int                        # 当前回合序号，从 1 开始
- year: int                        # 当前游戏年份，从 1 开始并由核心推进
- world_seed: int                  # 当前局随机种子，用于可复现筛选
- worldline_id: str                # 当前启用的主线世界线 ID
- worldline_stage: str             # 当前世界线阶段
- state_version: int               # 状态版本号，防止旧快照覆盖新快照
- content_version: str             # 当前内容和契约版本
```

约束：

- 禁止 AI 或插件直接修改。
- 禁止在 `DynamicWorldState` 中重复保存年份或世界线阶段。
- 状态更新必须通过带 `expected_version` 的核心提交接口完成。

### 5.4 DynamicWorldState

`DynamicWorldState` 保存可以随游戏演化的内容，但每次变化仍生成新的不可变快照。

```text
DynamicWorldState
- locations: tuple[LocationRecord, ...]          # 已发现或生成的地点
- characters: tuple[CharacterRecord, ...]        # 已出现或生成的人物
- relationships: tuple[RelationshipRecord, ...]  # 玩家与人物、势力之间的关系
- factions: tuple[FactionRecord, ...]            # 已启用势力和声望
- flags: tuple[WorldFlag, ...]                   # 世界和剧情标记
- items: tuple[ItemRecord, ...]                  # 持有物与关键物品
- plugin_states: tuple[PluginStateRecord, ...]   # 各插件命名空间私有状态
- generated_content: GeneratedContentStore       # 当前局生成的持久化内容
```

### 5.5 状态不变量

- `CoreWorldState` 是本局唯一权威年份和世界线来源。
- 所有状态快照不可原地修改。
- AI 只能产生提案，不能产生新的 `CoreWorldState`。
- 插件只能提交标准效果，不能持有状态写权限。
- 动态内容在写入前必须校验 ID 唯一性、引用完整性和数量预算。

## 6. 种子事件系统

### 6.1 SeedEvent

`SeedEvent` 是由策划、插件或基础内容提供的规则与剧情骨架，AI 可以围绕它扩写叙事或派生受控生成内容，但不能改写其数值和规则后果。

```text
SeedEvent
- id: str                                  # 全局唯一事件 ID，基础内容使用 base. 命名空间
- category: str                            # 事件分类，例如 daily、combat、mystery
- worldline_id: str | None                 # 所属世界线；普通支线可为空
- stage: str | None                        # 所属世界线阶段或事件阶段
- conditions: tuple[Condition, ...]        # 事件被选中前必须满足的条件
- weight: int                              # 合格候选中的权重，必须为非负整数
- location_ids: tuple[str, ...]            # 允许触发该事件的地点 ID 集合
- time_slots: tuple[str, ...]              # 允许触发的时间段集合
- required_state: StateRequirement | None  # 额外状态门槛；为空表示无额外门槛
- fallback_scene_text: str                 # 无 AI 或 AI 失败时使用的完整场景文本
- ai_prompt: str                           # 针对本事件的叙事扩写和生成提示
- choices: tuple[SeedChoice, ...]          # 2-4 个固定规则选项
- source_plugin_id: str | None             # 来源插件 ID；基础内容或 AI 生成内容可为空
```

### 6.2 SeedChoice

`SeedChoice` 是种子事件中的固定规则选项，玩家选择后由核心应用其标准效果。

```text
SeedChoice
- id: str                                  # 事件内唯一选项 ID，AI 不得修改
- fallback_label: str                      # 无 AI 时显示给玩家的选项文字
- result_hint: str                         # 供 AI 扩写结果文本使用的剧情提示
- fallback_result_text: str                # 无 AI 时展示的结果文本
- effects: tuple[StandardEffect, ...]      # 由核心白名单校验并应用的标准效果
```

### 6.3 NarrativeBrief

`NarrativeBrief` 是给 AI 的结构化剧情简报，用来约束扩写空间，避免 AI 只做同义改写。

```text
NarrativeBrief
- premise: str                             # 本事件的核心情境和戏剧问题
- tone: str                                # 叙事基调
- required_beats: tuple[str, ...]          # 扩写必须保留的剧情节点
- allowed_improvisation: tuple[str, ...]   # 允许 AI 自由创造的环境和临时细节
- forbidden_content: tuple[str, ...]       # 禁止 AI 引入的设定和规则变化
```

### 6.4 候选筛选

规则先按事件分类和世界线阶段缩小范围，再叠加地点、关系状态、前序选择、伏笔到期和必要条件。AI 只在规则提供的 2-3 个合格候选中选择，不直接检索或修改整个种子库。

## 7. AI 叙事扩写与内容生成

### 7.1 两种 AI 输出

AI 有两种常规结构化输出：

```text
NarrativeDraft
- seed_id: str                             # AI 选中的候选种子 ID
- scene_text: str                          # 扩写后的场景文本
- choices: tuple[NarrativeChoice, ...]     # 与种子选项一一对应的展示文本

NarrativeChoice
- choice_id: str                           # 必须与种子中的选项 ID 完全一致
- display_text: str                        # 选项显示文字
- result_text: str                         # 选择后展示的结果文本

ContentGenerationDraft
- derived_from_seed_id: str                # 本次生成所依据的种子事件 ID
- locations: tuple[LocationDraft, ...]     # AI 提议的新地点
- characters: tuple[CharacterDraft, ...]   # AI 提议的新人物
- events: tuple[EventDraft, ...]           # AI 提议的新事件
```

`NarrativeDraft` 只能改变展示文本；`ContentGenerationDraft` 可以提出新内容，但必须经过核心校验后才能登记。

### 7.2 生成内容提案

`LocationDraft`、`CharacterDraft`、`EventDraft`、`ChoiceDraft` 和 `EffectDraft` 中的 ID 只是本次 AI 响应内的临时 ID。核心校验通过后分配正式 ID，并写入当前局的 `GeneratedContentStore`。

正式生成内容必须记录：

- 正式 ID。
- 内容类型。
- 来源种子。
- 创建回合。
- 生成器版本和模型信息。
- 结构化定义。
- 当前状态。

### 7.3 内容生成限制

`ContentGenerationPolicy` 至少限制：

- 每回合最多生成多少地点、人物和事件。
- 每个事件最多有多少选项。
- 允许哪些标准效果类型。
- 每种效果的数值范围。
- 单个选项和单回合的效果总量。
- 禁止出现的死亡、突破、结局和世界线效果。
- 活跃伏笔数量。
- 每回合和每局模型调用次数。

建议初始限制：

```text
修为单次变化：0 到 +2
气运单次变化：-5 到 +5
关系单次变化：-10 到 +10
单个选项最多 2 个效果
单个事件最多 4 个选项
每回合最多 1 个新地点
每回合最多 1 个新人物
每回合最多 1 个新事件
```

超限结果必须拒绝，不能静默裁剪。

### 7.4 AI 输入

AI 只接收当前决策需要的受限上下文：

- 年份、地点和当前公开状态。
- 相关核心数值与叙事标签。
- 相关人物和势力关系。
- 最近两到三条事件簿摘要。
- 2-3 个合格种子事件及其规则选项。
- 当前允许的生成类型、数量和数值预算。
- 到期或允许提示的伏笔摘要。

普通叙事生成不得接收玩家隐藏的完整伏笔真相；只有负责回收特定伏笔的专门调用可以接收最小必要信息。

### 7.5 AI 禁止事项

- 不得直接修改任何状态。
- 不得修改年份、回合、世界线阶段和状态版本。
- 不得直接创建最终结局或新主线世界线。
- 不得判定死亡或突破成功。
- 不得生成超出预算的标准效果。
- 不得引用不存在的地点、人物或物品。
- 不得生成违反基础世界观的永久事实。
- 不得读取或输出用户 API Key。

### 7.6 失败处理

- AI 输出格式错误、非法 ID、非法引用或超限效果时，先重试一次。
- 重试仍失败时，丢弃本次生成提案，使用种子事件后备文本和核心效果。
- 没有 Key、网络失败、服务错误或 token 预算耗尽时，自动进入纯后备模式。
- 后备模式不产生新的 AI 生成地点、人物、事件或伏笔。

### 7.7 Key 与模型设置

- 课程 MVP 只启用一个主模型预设。
- Key 只保存在当前页面内存中，不进入存档、日志、URL 或数据库。
- 同一局锁定模型服务与模型，不允许局中切换。
- 每局默认 token 预算为 60k，最多 25 次模型调用。
- 叙事扩写、内容生成、伏笔评审和事件摘要都必须计入预算。
- 达到预算 80% 时提示玩家，达到 100% 时切换固定后备模式。
- 用量记录保存在当前存档或浏览器本地，不写入服务端数据库。

## 8. 事件簿与人物记忆

### 8.1 ChronicleEntry

`ChronicleEntry` 是一次事件结算后的结构化历史记录，保存事实、选择、效果和一到两句摘要。

```text
ChronicleEntry
- id: str                                  # 事件簿记录 ID
- turn: int                                # 发生回合
- year: int                                # 发生年份
- event_id: str                            # 实际执行的事件 ID
- choice_id: str                           # 玩家选择的选项 ID
- location_id: str | None                  # 发生地点
- involved_character_ids: tuple[str, ...]  # 涉及人物
- summary: str                             # 一到两句玩家可见摘要
- applied_effects: tuple[StandardEffect, ...]  # 实际应用的标准效果
- summary_source: str                      # ai 或 fallback
- tags: tuple[str, ...]                    # 可用于检索的叙事和伏笔标签
```

摘要由核心根据结构化事实生成基础版本，AI 可以润色；AI 失败时保留基础摘要。

### 8.2 CharacterMemory

`CharacterMemory` 保存人物对相关事件的引用和主观记忆，不复制完整事件簿。

```text
CharacterMemory
- character_id: str                        # 人物 ID
- chronicle_entry_ids: tuple[str, ...]      # 该人物经历过的事件簿记录
- perspective_summary: str                 # 该人物视角下的一到两句记忆
```

### 8.3 使用方式

- 游戏页可以展示事件簿摘要。
- AI 叙事只读取最近两到三条摘要和必要的相关人物记忆。
- 事件簿不得由 AI 改写已应用的实际效果和选择事实。

## 9. 伏笔系统

### 9.1 ForeshadowProposal

`ForeshadowProposal` 是 AI 提出的伏笔候选，提出后必须经过校验和第二个评审 agent。

```text
ForeshadowProposal
- source_event_id: str                     # 提出伏笔的事件 ID
- source_choice_id: str | None             # 触发伏笔的选项 ID
- content: str                             # 伏笔的隐藏内容
- payoff_tags: tuple[str, ...]             # 未来回收时可匹配的事件标签
- proposed_due_turn: int                   # 建议的到期回合，默认不超过提出后 10 回合
- stakes: str                              # 回收后的风险或收益
```

### 9.2 ForeshadowAssessment

`ForeshadowAssessment` 是第二个评审 agent 对伏笔候选的结构化评分。

```text
ForeshadowAssessment
- world_consistency: int                   # 0-100，是否符合世界设定
- causal_clarity: int                      # 0-100，因果链是否清楚
- payoff_feasibility: int                  # 0-100，未来是否能合理回收
- narrative_value: int                     # 0-100，叙事价值
- spoiler_risk: int                        # 0-100，提前泄露风险
- total_score: int                         # 0-100，综合评分
- recommendation: str                      # accept、revise 或 reject
- reason: str                              # 评分理由
```

### 9.3 ForeshadowRecord

`ForeshadowRecord` 是认证后保存的隐藏伏笔记录，玩家不可见，核心负责调度和响应。

```text
ForeshadowRecord
- id: str                                  # 伏笔记录 ID
- source_event_id: str                     # 来源事件 ID
- source_turn: int                         # 提出伏笔的回合
- content: str                             # 隐藏伏笔事实
- payoff_tags: tuple[str, ...]             # 回收事件匹配标签
- due_turn: int                            # 必须响应的最晚回合
- status: str                              # certified、due、resolved 或 expired
- assessment: ForeshadowAssessment         # 认证时的评分记录
```

### 9.4 认证和响应规则

1. 先进行确定性校验：来源事件存在、没有重复、没有违反世界线、没有超过活跃伏笔上限。
2. 第二个评审 agent 返回结构化评分。
3. 只有总分超过阈值，且世界观一致性和回收可行性均超过最低阈值，才能写入 `ForeshadowBook`。
4. 认证伏笔对玩家隐藏，只对核心调度和必要的回收生成可见。
5. 到期回合不得超过提出回合加 10。
6. 核心在到期前优先选择带匹配 `payoff_tags` 的事件；没有合适事件时触发核心后备回收事件。
7. 回收、升级、部分揭露或明确过期都必须产生具体世界后果，不能静默消失。

两个 agent 的评分不能替代确定性校验，也不能直接创建世界事实。

## 10. 扩展包机制

### 10.1 分发与信任

- 扩展包由作者提交，维护者审核后随站点一起发布。
- 公开访客不能上传或即时执行任意脚本。
- MVP 采用可信脚本模型：不承诺隔离恶意代码，审核是安全边界。
- 宿主不向插件提供模型 Key 或其他秘密。
- 插件出错时只停用该插件，当前游戏继续运行。
- 插件版本与游戏版本不兼容时禁止启用并显示原因。

### 10.2 扩展能力

插件可以通过宿主接口：

- 新增属性、地点、人物和行动。
- 新增种子事件和触发条件。
- 新增规则判定与结果。
- 新增结局。
- 读写自己的插件私有状态。
- 提供可供 AI 生成器使用的种子、模板和叙事简报。

插件不能：

- 修改核心回合顺序和主界面外壳。
- 修改其他插件的数据。
- 覆盖基础规则和基础结局。
- 绕过宿主接口直接修改游戏状态。
- 直接修改 `CoreWorldState`。

### 10.3 统一内容契约

基础内容、插件内容和 AI 生成内容使用同一套公开契约：

- 种子事件使用 `SeedEvent` 和 `SeedChoice`。
- 状态修改使用 `StandardEffect`。
- 插件内容在发布前注册；AI 生成内容在当前局校验后注册。
- AI 生成内容必须记录来源种子、创建回合和生成器版本。
- 插件和 AI 生成内容都不能直接修改玩家状态或核心世界状态。

### 10.4 官方独立扩展包

课程 MVP 只要求一个独立扩展包，由不负责核心模块开发的组员完成，并同时作为官方示例。扩展作者只能依赖公开契约和接入文档实现功能，不得修改核心模块内部代码。

最小验收范围：

- 1 个新地点。
- 2 个新事件。
- 1 个新条件或新行动。
- 1 个结局变化。
- 每个事件和结果都有完整后备文本。
- 能在启用后正常游玩、存档并重新加载。
- 开启、禁用和模拟故障时均符合文档约定。

## 11. 世界线与内容节奏

课程 MVP 采用固定骨架加受控生成：

- 第 3、6、10 年必定出现灵潮相关重大事件。
- 其余回合保证灵矿线获得足够出场次数。
- 核心负责世界线排期和保证推进。
- AI 可以在候选种子内选择具体事件，也可生成受控支线，但不能创建新的主线世界线。
- AI 生成的支线事件必须声明所属世界线或标记为 `side`，并受内容配额限制。
- 每条已启用世界线即使被玩家忽略，也必须继续推进，并至少每三年产生一次可见变化。
- 认证伏笔必须在十回合内得到响应，或产生明确的过期后果。

## 12. 界面与存档

### 12.1 页面

- 开始页：新游戏、继续游戏、已完成人物志、模型与预算设置。
- 游戏页：年份、地点、时局、属性、关系、物品、事件文本、已校验选项、事件簿和人物志。
- 结算区域：展示选择结果、实际效果、事件摘要和进入下一年的操作。
- 结局页：展示结局名称、关键选择、世界最终状态和重新开始入口。
- 玩家界面不展示隐藏伏笔真相，只展示由核心决定公开的线索。

### 12.2 存档

- 使用浏览器本地存档。
- 保留一个当前局和已完成人物志。
- 每回合结算后自动保存。
- 不做账号和云存档。
- 必须保存 `CoreWorldState`、`DynamicWorldState`、事件簿、人物记忆、生成内容、伏笔账本和插件状态。
- 插件私有状态和启用插件版本必须随存档保存。
- 存档必须记录模型用量但不记录 API Key。
- AI 生成内容必须保存正式 ID、来源种子、创建回合、结构化定义和版本信息。

### 12.3 运行环境

- 课程验收以本地启动 FastAPI、通过浏览器访问为主。
- 公网访问为可选增强，不作为课程交付门槛。
- 没有服务端模型 Key；模型服务由用户自己的 Key 驱动。
- 页面必须支持桌面浏览器，并保证手机端基本可读和可选择。
- 任何运行环境都不得输出或记录用户 Key。

## 13. 内容基调

- 轻快诙谐，但危险和失败有真实代价。
- 幽默来自人物性格、处境和修仙世界的反差，不依赖网络热梗。
- 允许出现温情和意外，但不把世界写成纯喜剧。
- 场景和结果文字目标为 100-200 个中文字符。
- AI 生成的地点和人物必须符合当前世界基调，不得随意引入现代网络梗或破坏境界体系。

## 14. 验收标准

### 14.1 游戏流程

- 新玩家能完成一局 10 回合游戏。
- 每回合都至少有一个可继续操作的选项。
- 每个事件至少有一个带代价的退路。
- 至少两种结局能够通过正常游玩到达。
- 至少出现一次跨三回合以上的选择后果。
- 至少出现一次被忽略后仍继续发展的世界线。
- 至少出现一条由 AI 生成并成功持久化的新地点、新人物或新事件。
- 事件簿能够记录每回合事件、选择和摘要，并在刷新后恢复。
- 至少一条认证伏笔在十回合内得到响应或产生明确过期后果。

### 14.2 AI 与后备

- 没有 Key、网络失败或模型报错时仍能完成整局。
- 非法种子、非法选项、非法引用或超限效果会被拒绝并回退。
- AI 不能直接修改核心世界状态、玩家状态或标准效果。
- 每局模型调用不超过 25 次。
- 达到 60k token 或 100% 预算后自动进入后备模式。
- 任何运行环境不得暴露或记录用户 Key。
- 普通叙事生成不能收到隐藏伏笔真相。

### 14.3 伏笔与事件簿

- 伏笔必须经过确定性校验和第二个评审 agent 评分。
- 只有超过阈值的伏笔才能写入隐藏账本。
- 认证伏笔到期十回合内必须被核心调度响应。
- 伏笔未响应时必须产生明确后果，不能静默丢失。
- 事件簿摘要不得改写已应用效果和选择事实。
- 人物记忆只保存关联事件和主观摘要，不复制完整事件。

### 14.4 插件

- 官方独立扩展包能增加新内容和新规则。
- 扩展由不负责核心模块的组员仅依靠公开文档和接入说明完成。
- 接入扩展时核心源码保持不变。
- 插件存档能够正确恢复。
- 插件出错时只停用插件。
- 不兼容插件不能启用。
- 插件内容与 AI 生成内容共用统一公开契约。

### 14.5 工程与协作

- 测试、Lint 和类型检查退出码均为 0。
- 正常、边界/失败、内容生成和伏笔契约测试均有断言。
- 演示一次故意引入错误导致测试失败，恢复后测试通过。
- GitHub Actions 至少有一次真实成功记录。
- 不提交 `.env`、API Key 或真实模型凭据。
- README 包含安装、运行、测试、模型配置和本地发行说明。
- 提供 MIT 许可证、插件作者指南、示例扩展包和贡献说明。
- 五人均有实际代码或测试提交，并至少审查一次他人的修改。
- 使用 Tag、发行 ZIP 和 `release/RELEASE.md` 完成可追溯发布。
- 提供 `docs/DESIGN.docx`，内容与最终实现一致。
