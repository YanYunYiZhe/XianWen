# XianWen MVP 产品需求文档

- 状态：Draft
- 更新时间：2026-11-10
- 产品代号：云州散修

## 1. 产品概述

XianWen 是一款单人中文修仙文字游戏。玩家在云州扮演一名散修，以每回合一年的节奏经历 10 年修行人生。世界会持续变化，玩家可以选择介入或回避；种子事件和规则保存世界事实，AI 负责在允许范围内扩写剧情。

MVP 的核心承诺：

> 规则是世界的事实来源，AI 是世界的表达层。

## 2. MVP 目标

玩家应能在浏览器中完成一局约 10-15 分钟的游戏，并清楚感受到：

1. 自己的选择会改变人物、关系和世界线。
2. 被忽略的事件也会继续发展。
3. 早期选择会在数回合后产生后续影响。
4. 没有 AI 服务时，游戏仍能完整游玩。
5. 不负责核心模块的组员可以依靠公开文档和示例扩展游戏内容与规则。

## 3. MVP 范围

### 包含

- 10 个年度回合，每回合代表一年。
- 单机、中文、浏览器本地运行；公网访问为课程后可选增强。
- 固定选项，不做自由文字输入。
- 轻规则判定与简单数值。
- 种子事件库、世界线推进和人物志。
- AI 剧情扩写与固定文本后备模式。
- 课程 MVP 只启用一个主模型预设，用户自带 API Key。
- 插件审核后随应用发布。
- 一个官方示例扩展包，同时作为组内独立扩展课程验收包。

### 不包含

- 账号系统、云存档和跨设备同步。
- 多人游戏。
- 自由文字行动。
- 复杂回合制战斗。
- 超大世界地图。
- 图片、音频或视频生成。
- 插件上传市场、评分系统或在线审核后台。
- 月程、逐日行动和精细日程模拟。
- 第二、第三个模型预设的课程验收。
- 团队外部作者参与课程验收。
- 对所有模型服务提供商的兼容承诺。

### 课程交付硬性范围

课程验收以以下内容为硬性门槛：

1. 一个完整的 10 回合单局流程，可从新游戏走到结局并重新开始。
2. 一个主模型预设加固定后备文本；测试和本地演示不依赖真实模型网络。
3. 一个由不负责核心模块的组员独立完成的扩展包，可启用、禁用、故障隔离并随存档恢复。
4. 正常、边界/失败和扩展契约测试；一次故意引入错误并确认测试失败的演示。
5. GitHub Actions 至少一次真实成功 CI，执行构建、测试和基础静态检查。
6. 五人均有代码或测试贡献、至少一次具体 Review，并使用 Tag、发行 ZIP 和 `release/RELEASE.md` 完成可追溯发布。
7. `README.md`、`LICENSE`、`docs/DESIGN.docx` 和组内扩展接入说明齐全。

### 课程后延期项

以下内容不纳入课程 MVP 的硬性验收：

- 公网部署、CD、部署 Webhook 和公开 URL 健康检查。
- 除主预设外的第二、第三个模型适配。
- 团队外部作者、插件市场、热加载和社区运营。
- 20 回合、第三结局、第三世界线和移动端精细适配。

## 4. 核心循环

每回合按以下顺序执行：

1. 代码根据年份、地点、事件分类、世界线阶段和必要条件筛选 2-3 个合格种子事件。
2. AI 从候选中选择一个种子，并扩写场景、选项文字及每个选项对应的结果文本。
3. 玩家看到场景和 2-4 个固定选项，做出选择。
4. 代码应用该选项的规则后果，修改数值与状态。
5. 游戏展示该选项预先写好的结果文本。
6. 年份推进，世界线继续发展，进入下一回合。

AI 只在玩家选择前进行常规介入一次。玩家选择后不再调用 AI。终局允许额外调用一次 AI 生成人物志总结；所有调用都计入单局上限。

### 回合约束

- 玩家不能自由输入行动。
- 每个事件至少有一个带代价的退路，例如暂避、离开、保守处理或付出资源。
- 任何场景都不能出现没有可继续操作的死局。
- 失败必须产生具体后果，不能出现“什么也没发生”的结果。
- AI 不能决定死亡、突破成功或最终结局。

## 5. 角色状态

MVP 使用有限的核心数值，避免所有设定都变成复杂计算。

### 核心数值与状态

- 身份与出身
- 境界与修为
- 寿元
- 伤势
- 心境
- 青岚宗声望
- 散修盟声望
- 关键人物好感
- 持有物
- 当前地点
- 年份
- 短期主线进度
- 结局标记

### 叙事标签

以下内容先作为布尔标记、文本标签或事件条件使用，不在 MVP 中引入复杂数值公式：

- 灵根
- 业力
- 道心
- 因果债
- 秘密

铁律：AI 只扩写剧情；所有数值、状态、死亡、突破和结局都由代码修改与判定。

## 6. 种子事件系统

每个种子事件至少包含：

- 唯一 ID。
- 事件分类。
- 所属世界线及阶段。
- 触发条件。
- 权重。
- 地点、时间和状态要求。
- 基础场景文本。
- 2-4 个固定选项。
- 每个选项的规则后果。
- 每个选项的基础结果文本。
- AI 扩写提示。

种子事件本身必须是完整可玩的最小事件。AI 可以参考种子扩写，不必逐字复述；但选项数量、选项 ID、规则后果和后续影响必须以种子为准。

### 事件示例

- 触发条件：地点=偏院，时间=夜，业力<0。
- 基础场景：你听见墙外有人埋东西，似有婴啼。
- 选项 A：装没听见。后果：业力变化，安全。
- 选项 B：扒墙缝查看。后果：获得物品或惊动巡逻弟子，具体由规则判定。
- 选项 C：暂时离开。后果：付出时间或机会成本，避免当前危险。

MVP 不提供“自由输入后由 AI 判断”的选项。

### 候选筛选

规则先按事件分类和世界线阶段缩小范围，再叠加地点、关系状态、前序选择和必要条件。AI 只在规则提供的 2-3 个合格候选中选择，不直接检索或修改整个种子库。

## 7. AI 剧情扩写

### 输入

AI 只接收当前事件相关的局势摘要：

- 年份、地点和当前公开状态。
- 相关核心数值与叙事标签。
- 相关人物和势力关系。
- 最近两到三条人物志。
- 2-3 个合格种子事件及其允许的选项和结果。

### 输出

AI 必须返回：

- 选中的种子事件。
- 场景扩写文本。
- 各选项的显示文字。
- 每个选项对应的结果文本，供玩家选择后展示。

场景和单个结果文本的目标长度为 100-200 个中文字符，具体可在内容制作阶段微调。

### 禁止事项

- 不得修改数值或状态。
- 不得增删选项或改变选项 ID。
- 不得新增永久地点、关键人物、关键物品或结局条件。
- 不得自行判定突破、死亡或结局。
- 不得依赖完整聊天历史维持世界连续性。

### 失败处理

- 输出格式错误、选择不存在的种子、选项 ID 不匹配或越权修改状态时，先重试一次。
- 重试仍失败时，使用种子事件的基础文本和基础结果。
- 没有 Key、网络失败、服务错误或 token 预算耗尽时，自动进入后备模式。

## 8. 用户自带 Key 与模型设置

### 支持服务

课程 MVP 只启用一个主模型预设。DeepSeek、千问、智谱 GLM 作为候选，完成实测后选择一个作为主预设；其余两个延期，不参与课程验收。

主预设提供：

- 服务注册与获取 Key 的入口。
- 一个默认模型。
- 一个经过验证的有限模型列表。
- 对应的服务接口配置。

服务端仍只允许白名单中的预设和模型；未启用的预设返回明确错误。MVP 不提供任意自定义接口地址，也不提供自由文本模型名输入。

### Key 安全

- Key 只保存在当前页面内存中。
- 不写入浏览器本地存储、存档、MySQL、日志或分析数据。
- 关闭或刷新页面后必须重新输入。
- 请求由服务端即时转发给模型服务。
- 服务端只做即时转发，不持久化、不记录 Key。
- 不在界面、URL、错误信息或日志中回显完整 Key。
- 用户可选使用固定后备模式，完全不输入 Key。

### 使用限制

- 同一局锁定模型服务与模型，不允许局中切换。
- 允许重新输入 Key，但不允许中途换模型。
- 每局默认 token 预算为 60k。
- 达到预算 80% 时提示用户。
- 达到预算 100% 时自动切换固定后备模式。
- 每局最多 25 次模型调用，包含重试和终局总结。
- token 用量优先采用服务商返回的数据；缺失时显示估算值。
- 用量记录保存在当前存档或浏览器本地，不写入 MySQL。
- 服务预设、模型选择和预算可以保存在浏览器本地，Key 永不保存。

## 9. 扩展包机制

### 分发与信任

- 扩展包由作者提交，维护者审核后随站点一起发布。
- 公开访客不能上传或即时执行任意脚本。
- MVP 采用可信脚本模型：不承诺隔离恶意代码，审核是安全边界。
- 宿主不向插件提供模型 Key 或其他秘密。
- 插件出错时只停用该插件，当前游戏继续运行。
- 插件版本与游戏版本不兼容时禁止启用并显示原因。

### 扩展能力

插件可以通过宿主接口：

- 新增属性、地点、人物和行动。
- 新增种子事件和触发条件。
- 新增规则判定与结果。
- 新增结局。
- 读写自己的插件私有状态。

插件不能：

- 修改核心回合顺序和主界面外壳。
- 修改其他插件的数据。
- 覆盖基础规则和基础结局。
- 绕过宿主接口直接修改游戏状态。

每个插件事件和每个选项结果都必须提供基础后备文本，否则插件校验不通过。

### 官方独立扩展包

课程 MVP 只要求一个独立扩展包，由不负责核心模块开发的组员完成，并同时作为官方示例。扩展作者只能依赖公开契约和接入文档实现功能，不得修改核心模块内部代码。

最小验收范围：

- 1 个新地点。
- 2 个新事件。
- 1 个新条件或新行动。
- 1 个结局变化。
- 每个事件和结果都有完整后备文本。
- 能在启用后正常游玩、存档并重新加载。
- 开启、禁用和模拟故障时均符合文档约定。

课程不要求团队外部作者参与。外部作者可以作为课程后社区验证项，但不纳入本次验收。

## 10. 世界线与内容节奏

课程 MVP 采用固定骨架加局部随机：

- 第 3、6、10 年必定出现灵潮相关重大事件。
- 其余回合保证灵矿线获得足够出场次数。
- 规则负责排期和保证世界线推进。
- AI 只在当前合格种子中选择具体事件，不决定整条世界线的排期。

课程 MVP 世界线包括：

- 灵潮将至：贯穿全局的主线。
- 灵矿之争：青岚宗与散修盟的冲突。

旧债线属于课程后内容。任何已启用世界线即使被玩家忽略，也必须继续推进，并至少每三年产生一次可见变化。

## 11. 界面与存档

### 页面

- 开始页：新游戏、继续游戏、已完成人物志、模型与预算设置。
- 游戏页：年份、地点、时局、属性、关系、物品、事件文本、固定选项和人物志。
- 结算区域：展示选择结果、数值变化及进入下一年的操作。
- 结局页：展示结局名称、关键选择、世界最终状态和重新开始入口。

### 存档

- 使用浏览器本地存档。
- 保留一个当前局和已完成人物志。
- 每回合结算后自动保存。
- 不做账号和云存档。
- 插件私有状态和启用插件版本必须随存档保存。

### 运行环境

- 课程验收以本地启动 FastAPI、通过浏览器访问为主。
- 公网访问为可选增强，不作为课程交付门槛。
- 没有服务端模型 Key；模型服务由用户自己的 Key 驱动。
- 页面必须支持桌面浏览器，并保证手机端基本可读和可选择。
- 任何运行环境都不得输出或记录用户 Key。

## 12. 内容基调

- 轻快诙谐，但危险和失败有真实代价。
- 幽默来自人物性格、处境和修仙世界的反差，不依赖网络热梗。
- 允许出现温情和意外，但不把世界写成纯喜剧。
- 场景和结果文字目标为 100-200 个中文字符。

## 13. 验收标准

### 游戏流程

- 新玩家能完成一局 10 回合游戏。
- 每回合都至少有一个可继续操作的选项。
- 每个事件至少有一个带代价的退路。
- 至少两种结局能够通过正常游玩到达。
- 至少出现一次跨三回合以上的选择后果。
- 至少出现一次被忽略后仍继续发展的世界线。

### AI 与后备

- 没有 Key、网络失败或模型报错时仍能完成整局。
- 非法种子、非法选项或越权修改状态会被拒绝并回退。
- 每局模型调用不超过 25 次。
- 达到 60k token 或 100% 预算后自动进入后备模式。
- 任何运行环境不得暴露或记录用户 Key。

### 插件

- 官方独立扩展包能增加新内容和新规则。
- 扩展由不负责核心模块的组员仅依靠公开文档和接入说明完成。
- 接入扩展时核心源码保持不变。
- 插件存档能够正确恢复。
- 插件出错时只停用插件。
- 不兼容插件不能启用。

### 工程与协作验收

- 测试、Lint 和类型检查退出码均为 0。
- 正常、边界/失败和扩展契约测试均有断言。
- 演示一次故意引入错误导致测试失败，恢复后测试通过。
- GitHub Actions 至少有一次真实成功记录。
- 不提交 `.env`、API Key 或真实模型凭据。
- README 包含安装、运行、测试、模型配置和本地发行说明。
- 提供 MIT 许可证、插件作者指南、示例扩展包和贡献说明。
- 五人均有实际代码或测试提交，并至少审查一次他人的修改。
- 使用 Tag、发行 ZIP 和 `release/RELEASE.md` 完成可追溯发布。
- 提供 `docs/DESIGN.docx`，内容与最终实现一致。

## 14. 待定项

以下内容尚未最终锁定，不应在实现中自行补成不可回退的硬约束：

1. 内容预算：10 回合内的种子事件、出身、地点和每种结局的具体数量。
2. 种子筛选条件的具体分类体系。
3. 唯一主模型预设及其默认模型、模型列表和接口地址。
4. 负责独立扩展的非核心成员及联调时间。
5. 类型检查、Lint 和测试命令。
6. GitHub 仓库及默认分支。
