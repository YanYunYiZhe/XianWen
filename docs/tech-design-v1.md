# XianWen v1 技术方案

- 状态：Draft v1.1
- 更新时间：2026-11-18
- 关联文档：`docs/prd-v1.md`、`docs/契约文档.md`、`docs/接口文档.md`、`docs/设计说明.md`
- 适用范围：XianWen 课程 MVP 的工程实现、受控 AI 内容生成、插件开发、事件簿、伏笔、测试与本地发行

## 1. 文档目的

本文档描述 XianWen 目标架构的技术实现方式，作为核心、Web、AI、插件、持久化和测试的共同依据。

产品范围以 `docs/prd-v1.md` 为准；公开接口以 `docs/接口文档.md` 为准；字段和校验以 `docs/契约文档.md` 为准；设计理由以 `docs/设计说明.md` 为准。

## 2. 技术目标

1. 游戏规则和世界事实由确定性的 Python 核心执行。
2. AI 可以生成叙事和结构化内容提案，但不能直接修改状态。
3. 核心状态和动态世界状态分离，所有状态以不可变快照提交。
4. AI 生成的地点、人物、事件、选项和效果必须校验、登记并随存档保存。
5. 事件簿保存每回合事件、选择、实际效果和一到两句摘要。
6. 伏笔经过提案、确定性校验和第二个评审 agent 评分后认证，并由核心在十回合内调度。
7. AI 不可用时仍可通过种子后备文本完成游戏。
8. 插件内容与 AI 生成内容共用公开契约和效果白名单。
9. 用户 API Key 只存在页面内存和单次服务端请求中。
10. 本地和 CI 使用统一测试、Lint、类型检查和构建命令。

## 3. 核心技术选型

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.12+ | 核心、Web、插件和校验 |
| Web 框架 | FastAPI | 页面路由、回合接口和模型代理 |
| 模板 | Jinja2 | 服务端渲染和 HTMX 片段 |
| 局部交互 | HTMX | 提交选择、更新场景和结算区域 |
| 客户端状态 | Alpine.js | 临时 Key、本地存档和页面交互 |
| 校验 | Pydantic | 请求、响应、存档、插件和 AI 输出校验 |
| HTTP 客户端 | httpx | 调用主模型服务 |
| 工程管理 | uv | Python 版本、虚拟环境和依赖 |
| 测试 | pytest | 核心、AI、插件、存档和伏笔测试 |
| Lint / 格式 | ruff | 静态检查和格式检查 |
| 类型检查 | mypy | Python 静态类型检查 |
| CI | GitHub Actions | 至少一次真实成功记录 |
| 存档 | 浏览器 `localStorage` | 通过可替换仓储层封装 |
| 部署 | 单个 FastAPI 服务；Docker 可选 | 课程验收以本地发行为主 |

## 4. 总体架构

```text
┌────────────────────────────────────────────┐
│ 浏览器                                     │
│ Jinja2 + HTMX + Alpine.js                  │
│ localStorage：完整 GameState               │
│ 页面内存：用户 API Key                     │
└───────────────────┬────────────────────────┘
                    │ 同源 HTTP
                    ▼
┌────────────────────────────────────────────┐
│ FastAPI 服务                               │
│                                            │
│ web          页面、请求和公开投影展示       │
│ core         状态迁移、效果、事件簿、伏笔   │
│ generation   内容生成校验与正式 ID 分配     │
│ plugins      插件加载、校验、注册和隔离     │
│ ai           叙事生成、内容提案、伏笔评分   │
│ persistence  存档契约、版本和迁移           │
└───────────────────┬────────────────────────┘
                    │ HTTPS
                    ▼
┌────────────────────────────────────────────┐
│ 一个主模型服务预设                         │
└────────────────────────────────────────────┘
```

服务端不保存玩家会话。`GameState`、生成内容、事件簿、伏笔和插件状态由浏览器保存，每次请求提交当前快照，服务端校验后返回新快照。

## 5. 分层与依赖方向

### 5.1 Web 层

负责：

- 开始页、游戏页、结算页和结局页。
- 接收 HTMX 请求并渲染 HTML 片段。
- 读取和转发临时 API Key。
- 展示 `RenderedEvent`、事件簿、人物志和公开世界投影。
- 保存和恢复 `GameState`。

不得负责：

- 筛选种子事件。
- 应用规则效果。
- 推进年份和世界线。
- 认证伏笔。
- 直接调用模型服务。
- 展示隐藏伏笔真相。

### 5.2 核心层

负责：

- `CoreWorldState`、`DynamicWorldState` 和 `GameState` 迁移。
- 候选种子筛选。
- 标准效果白名单校验和应用。
- AI 生成内容的结构、引用、数量和数值校验。
- 分配正式内容 ID。
- 事件簿写入。
- 伏笔认证、到期调度和响应。
- 死亡、突破和结局判定。
- 生成公开世界投影和受限 AI 上下文。

核心不得依赖 FastAPI、Jinja2、HTMX、浏览器存储或模型 SDK。

### 5.3 AI 层

负责：

- 调用主模型服务。
- 生成 `NarrativeDraft`。
- 生成 `ContentGenerationDraft`。
- 提出 `ForeshadowProposal`。
- 生成 `ForeshadowAssessment`。
- 生成事件摘要草稿。
- 处理超时、重试、预算、脱敏和后备切换。
- 普通叙事只接收公开世界投影。

不得负责：

- 修改状态。
- 应用效果。
- 认证伏笔。
- 推进世界线。
- 决定死亡、突破或结局。
- 读取隐藏伏笔真相用于普通叙事。

### 5.4 插件层

负责：

- 扫描插件目录并读取 `plugin.toml`。
- 校验插件清单、内容、ID、版本和后备文本。
- 注册地点、人物、种子事件、行动、结局和可选规则。
- 隔离单个插件的加载和运行错误。
- 管理插件私有状态命名空间。

插件不能直接修改 `GameState`、`CoreWorldState` 或其它插件状态。

### 5.5 持久化层

负责：

- 定义带版本号的 JSON 存档契约。
- 保存和恢复核心/动态世界状态。
- 保存 AI 生成内容、事件簿、人物记忆和伏笔账本。
- 保存启用插件 ID、版本和私有状态。
- 保存模型用量，不保存 API Key。
- 执行存档迁移。

## 6. 状态设计

```text
GameState
- player: PlayerState
- world: WorldSnapshot
- chronicle: tuple[ChronicleEntry, ...]
- foreshadows: ForeshadowBook

WorldSnapshot
- core: CoreWorldState
- dynamic: DynamicWorldState
```

### 6.1 CoreWorldState

只有核心状态迁移函数可以生成新版：

- 回合
- 年份
- 随机种子
- 主线世界线
- 世界线阶段
- 状态版本
- 内容版本

提交时检查 `expected_version`，防止旧快照覆盖新快照。

### 6.2 DynamicWorldState

保存：

- 地点和人物
- 势力和关系
- 世界标记
- 物品
- 插件私有状态
- 当前局 AI 生成内容

AI 和插件不能持有写引用，只能提交经过校验的提案或标准效果。

## 7. 回合数据流

### 7.1 开始回合

1. 浏览器恢复 `GameState` 或创建新游戏。
2. 服务端校验状态版本、结构和内容版本。
3. 核心筛选 2-3 个候选种子。
4. 核心检查到期伏笔和允许的回收事件。
5. AI 接收公开投影、候选种子和生成预算。
6. AI 返回叙事草稿和可选内容生成提案。
7. 核心校验叙事和生成内容。
8. 合法生成内容分配正式 ID 并写入 `GeneratedContentStore`。
9. 合法叙事转换为 `RenderedEvent`；失败时使用后备文本。
10. 浏览器展示事件和已校验选项。

### 7.2 处理选择

1. 浏览器提交状态快照、`RenderedEvent`、`choice_id` 和状态版本。
2. 服务端校验 `RenderedEvent` 与来源种子或生成事件一致。
3. 核心解析规则效果，不读取 AI 文本作为效果依据。
4. 核心应用 `StandardEffect` 并生成新世界快照。
5. 核心写入 `ChronicleEntry` 和人物记忆引用。
6. AI 可生成摘要草稿；失败时使用核心模板摘要。
7. 伏笔候选进入确定性校验和第二个评审 agent。
8. 合格伏笔写入隐藏 `ForeshadowBook`。
9. 核心检查到期伏笔并调度响应。
10. 核心推进年份和世界线，返回新 `GameState`。
11. 浏览器保存新状态。

### 7.3 原子性

内容生成和状态提交必须遵守：

- 提案整体接受或整体拒绝。
- 不允许只登记一个新人物但丢弃其关联事件。
- 效果应用、事件簿写入和状态版本递增必须属于同一提交。
- 伏笔认证失败不得部分写入。
- 插件加载失败不得污染已有注册表。

## 8. AI 契约

### 8.1 NarrativeDraft

只允许：

- 场景文本
- 选项显示文字
- 结果文本

选项 ID、数量和规则效果必须与种子一致。

### 8.2 ContentGenerationDraft

允许提出：

- 新地点
- 新人物
- 新事件
- 新选项
- 受限标准效果

所有 ID 都是临时 ID，正式 ID 由核心分配。

### 8.3 生成限制

`ContentGenerationPolicy` 至少限制：

- 每回合新增实体数量
- 每个事件选项数量
- 每个选项效果数量
- 效果类型和数值范围
- 单回合总效果预算
- 禁止效果
- 活跃伏笔上限
- 模型调用次数

超限结果必须拒绝，不能静默裁剪。

### 8.4 失败处理

- 格式或契约错误：重试一次。
- 重试失败：丢弃 AI 内容，使用种子后备。
- 没有 Key、网络失败或预算耗尽：进入纯后备模式。
- 后备模式不新增 AI 生成内容或伏笔。

## 9. 事件簿

每次选择结算后写入结构化记录：

- 回合和年份
- 事件 ID
- 选项 ID
- 地点和涉及人物
- 实际应用效果
- 一到两句摘要
- 摘要来源
- 检索标签

摘要由核心模板生成基础版本，AI 可以润色但不能改写事实。

人物记忆保存关联事件簿 ID 和主观摘要，不复制完整事实。

## 10. 伏笔

### 10.1 流程

```text
ForeshadowProposal
→ 确定性校验
→ ForeshadowAssessment
→ 阈值认证
→ ForeshadowRecord
→ 到期调度
→ resolve / escalate / expire
```

### 10.2 确定性校验

- 来源事件和选项存在。
- 没有重复伏笔。
- 不违反世界线和基础设定。
- 没有超过活跃伏笔上限。
- `due_turn <= source_turn + 10`。
- 至少有一种允许的回收方式。

### 10.3 评分

评分维度：

- 世界观一致性
- 因果清晰度
- 回收可行性
- 叙事价值
- 泄露风险

只有总分和关键维度均超过阈值才认证。

### 10.4 到期调度

核心在每回合检查到期伏笔：

- 优先选择带匹配 `payoff_tags` 的事件。
- 没有合适事件时使用核心后备回收事件。
- 不能静默删除。
- 过期必须产生明确后果。

### 10.5 私密性

普通叙事生成只接收公开世界投影。隐藏伏笔内容只提供给核心授权的回收事件生成，并由日志脱敏和输出校验保护。

## 11. Web 与交互

- 游戏页展示年份、地点、公开状态、事件文本、已校验选项、事件簿和人物志。
- 结算区域展示选择结果、实际效果和摘要。
- 隐藏伏笔不进入 HTML、公开接口或普通模型上下文。
- Jinja2 自动转义 AI、插件和玩家输入文本。
- API Key 只在页面内存和单次服务端请求中存在。

## 12. 存档设计

存档必须包含：

- 存档版本
- `GameState`
- `CoreWorldState`
- `DynamicWorldState`
- `GeneratedContentStore`
- 事件簿和人物记忆
- 伏笔账本
- 启用插件 ID、版本和私有状态
- 模型用量
- 内容版本和生成器版本

存档不得包含：

- API Key
- 真实模型凭据
- 未脱敏请求头
- Python 函数对象

存档加载前必须经过 Pydantic 校验；迁移失败必须明确报错，不得静默丢弃未知字段。

## 13. 插件系统

插件包结构：

```text
plugins/<plugin-id>/
├── plugin.toml
├── content/
│   ├── locations.toml
│   ├── characters.toml
│   ├── events.toml
│   └── endings.toml
└── rules.py        # 可选
```

加载流程：

1. 扫描插件目录。
2. 读取并校验 `plugin.toml`。
3. 读取并校验声明式内容。
4. 加载可选规则模块。
5. 校验 ID 唯一性、命名空间和版本兼容。
6. 注册到冻结的 `ContentRegistry`。

AI 生成内容使用与插件相同的 `SeedEvent`、`StandardEffect` 和记录契约，但不写入发布注册表，而写入当前局 `GeneratedContentStore`。

## 14. 本地运行与发行

- 使用单个 FastAPI 服务提供页面、静态资源和模型代理。
- 按 README 在干净目录安装依赖、启动服务并完成一次 10 回合流程。
- 发行物可以是可运行目录或 ZIP；Docker 可选。
- 公网部署不是课程硬性门禁。
- 发行前验证生成内容、事件簿和伏笔在刷新后仍能恢复。

## 15. CI 与质量门禁

GitHub Actions 在 PR 和分支推送时运行：

```powershell
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest
uv build
```

测试不得调用真实模型服务，AI 使用 mock 或固定响应。

要求：

- 至少覆盖无 Key 的完整后备流程。
- 覆盖生成内容超限拒绝。
- 覆盖非法引用和禁止效果。
- 覆盖事件簿持久化。
- 覆盖伏笔评分阈值、十回合到期和后备回收。
- 至少保留一次真实成功的 CI 记录。

## 16. 测试范围

- 核心/动态状态快照和版本冲突。
- 年份和世界线只能由核心推进。
- 候选种子筛选。
- 标准效果应用和越界拒绝。
- AI 叙事草稿校验和后备。
- AI 生成地点、人物、事件、选项和效果。
- 生成内容正式 ID、持久化和恢复。
- 事件簿事实、摘要和人物记忆。
- 伏笔确定性校验、评分、认证和到期调度。
- 插件加载、禁用、故障隔离和存档恢复。
- API 请求校验和 Key 脱敏。
- 存档序列化、反序列化和迁移。
- 一次故意引入错误导致测试失败，恢复后通过。

## 17. 安全约束

- 禁止提交 `.env`、真实 Key 或平台凭证。
- Key 只存在页面内存和单次服务端请求。
- 服务端只允许预设服务和白名单模型。
- 普通叙事不得接收隐藏伏笔真相。
- 日志不得记录 Key、完整请求体、敏感请求头或隐藏伏笔。
- Jinja2 自动转义。
- AI 输出和插件数据必须经过 Pydantic 和核心契约校验。
- 模型输出永远不能直接修改状态。
- 生成内容不得访问网络、用户 Key 或其他插件私有状态。

## 18. 实施阶段

### 阶段一：最小核心回合

- 固定事件和两个选项。
- 核心状态迁移和单元测试。
- 不接 AI。

### 阶段二：状态分层和种子契约

- `CoreWorldState` + `DynamicWorldState`
- `SeedEvent` + `SeedChoice`
- `NarrativeDraft` + `RenderedEvent`
- 后备文本和种子筛选

### 阶段三：受控内容生成

- `ContentGenerationDraft`
- `ContentGenerationPolicy`
- `GeneratedContentStore`
- 地点、人物、事件和选项校验

### 阶段四：事件簿

- 结构化事件记录
- 核心摘要和 AI 润色
- 人物记忆引用
- 存档恢复

### 阶段五：伏笔

- 提案和评分
- 隐藏账本
- 十回合到期调度
- 后备回收事件

### 阶段六：插件和发行

- 插件加载、校验、隔离
- 官方独立扩展包
- CI、Tag 和发行 ZIP

## 20. 验收映射

技术方案至少支撑以下课程验收：

- 无 Key 时可完成 10 回合游戏。
- AI 非法输出和超限内容会被拒绝并回退。
- 核心/动态状态分层且年份只能由核心推进。
- AI 生成地点、人物、事件和选项可持久化恢复。
- 事件簿记录事实和摘要。
- 伏笔经过评审、认证并在十回合内响应。
- 插件可增加内容与规则，并在失败时隔离。
- 用户 Key 不进入存档、日志或仓库。
- CI 可阻止失败代码合并并保留真实成功记录。
- 发行 ZIP 可在新目录按 README 运行并完成试玩。
