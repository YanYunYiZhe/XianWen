## 1. 文档目的

本文档说明 XianWen 核心架构的设计理由、模块职责、回合数据流和阶段边界。

它回答“为什么这样设计”，而不是逐一列举接口或字段：

- 接口和调用边界 → `docs/接口文档.md`
- 数据结构和校验规则 → `docs/契约文档.md`
- 产品范围和验收要求 → `docs/prd-v1.md`

## 2. 核心设计原则

### 2.1 代码拥有规则，AI 只负责内容

所有确定性规则必须由 Python 代码执行：

- 数值和状态变化
- 事件候选筛选
- 世界线排期
- 死亡、突破和结局判定
- 插件内容是否合法
- 标准效果是否允许

AI 可以：

- 从规则提供的 2-3 个候选中选择事件
- 扩写场景文字
- 扩写选项显示文字
- 扩写每个选项对应的结果文字

AI 不可以：

- 修改 `GameState`
- 修改选项 ID 或数量
- 修改标准效果
- 新增永久地点、人物、物品或结局条件
- 决定死亡、突破或最终结局

### 2.2 内容、展示和规则分离

需要区分以下概念：

| 概念 | 作用 |
| --- | --- |
| `SeedEvent` | 规则和内容的真实来源 |
| `NarrativeDraft` | AI 返回的待校验叙事草稿 |
| `RenderedEvent` | 玩家当前回合实际看到的已校验内容 |
| `StandardEffect` | 唯一允许修改状态的受控效果 |
| `TurnResult` | 一次选择后的新状态和展示结果 |

如果把它们混成一个 `Event`，会出现：

- AI 文本被误当成规则依据
- 插件无法表达条件、世界线和多类型效果
- 无法验证 AI 是否越权
- 无法可靠回退到固定文本
- 存档无法区分内容来源和展示版本

### 2.3 状态不可变

`GameState` 采用不可变数据模型。

每次合法选择都会生成新的状态快照：

```text
旧 GameState
→ 校验选择和效果
→ 新 GameState
→ TurnResult
```

这样便于：

- 测试相同输入得到相同输出
- 回滚非法效果
- 保存每回合状态
- 插件和 Web 无法偷偷改状态

### 2.4 失败关闭和后备优先

任何 AI 或插件输出都必须可校验。

失败时不能“猜一个结果继续”，而应：

```text
AI 输出非法
→ 重试一次
→ 仍失败则使用 SeedEvent 后备文本

单个插件加载或运行失败
→ 禁用该插件
→ 基础内容和其它插件继续工作
```

### 2.5 插件是受控内容包，不是核心补丁

插件可以增加内容和规则能力，但不能修改宿主核心实现。

插件允许增加：

- 地点
- 人物
- 行动
- 种子事件和条件
- 规则判定和结果
- 结局
- 插件私有状态
- 受控标准效果

插件不允许：

- 修改核心回合顺序
- 修改主界面外壳
- 修改其他插件数据
- 覆盖基础规则和基础结局
- 直接修改 `GameState`
- 访问用户 API Key

## 3. 完整回合数据流

目标流程：

```text
1. 浏览器恢复已提交 GameState
2. 核心根据状态、地点、年份、世界线阶段和条件筛选 2-3 个候选 SeedEvent
3. AI 在候选集中选择一个并返回 NarrativeDraft
4. 校验 NarrativeDraft 的 seed_id、choice_id 和字段权限
5. 合法则生成 RenderedEvent；非法则使用 SeedEvent 后备文本
6. 玩家选择一个固定选项
7. 核心根据 SeedEvent 的 choice_id 解析 StandardEffect
8. 核心应用效果并生成新的 GameState
9. 返回 TurnResult，展示已校验的 result_text
10. 浏览器保存新 GameState、回合上下文和插件状态
```

关键点：

- AI 只在玩家选择前常规介入一次。
- 玩家选择后不再调用 AI。
- 规则效果来自种子事件，不来自 AI 文本。
- 结果文本可以来自 AI 草稿，但必须已经过校验。
- 年份推进、世界线和结局由核心控制。

## 4. 第一阶段与完整 MVP 的边界

### 4.1 第一阶段已实现

- `GameState` 只有 `year / cultivation / ended`
- 一个固定事件 `base.morning_training`
- 两个固定选项
- 固定场景和结果文本
- 不接入 AI
- 不实现完整插件系统
- 核心单元测试验证最小回合

第一阶段的目标是验证最小垂直切片：

```text
new_game
→ get_current_event
→ apply_choice
→ TurnResult
```

### 4.2 完整 MVP 目标

- 完整 10 回合流程
- 2 个结局、2 条世界线
- 完整状态字段
- 种子事件筛选和 AI 叙事扩写
- 固定后备路径
- 可启用、禁用和故障隔离的独立扩展包
- 插件私有状态和存档恢复

### 4.3 当前代码的定位

当前 `Event` 不是最终 `SeedEvent`，而是第一阶段固定可玩事件。

后续演进方向：

```text
当前固定 Event
→ 拆分为 SeedEvent + 后备渲染
→ 增加候选筛选
→ 增加 AI NarrativeDraft 校验
→ 增加 ContentRegistry
→ 增加完整 StandardEffect
```

在接口冻结前，不应让 B/C 基于当前最小 `Event` 假设插件只能添加事件。

## 5. 模块职责

### 5.1 Core

负责：

- 状态模型和状态迁移
- 候选种子筛选
- 世界线排期
- 标准效果应用
- 死亡、突破和结局判定
- 生成 AI 可见的受限上下文

不负责：

- HTTP 和模板
- 浏览器存储
- 模型请求
- 插件目录扫描

### 5.2 Plugins

负责：

- 扫描和读取插件包
- 校验清单、内容和版本
- 注册插件内容
- 隔离插件加载和运行错误
- 管理插件命名空间和私有状态

不负责：

- 绕过核心修改状态
- 决定核心回合顺序
- 修改基础规则和基础结局

### 5.3 Web

负责：

- 开始页、游戏页和结局页
- 提交选择请求
- 展示 `RenderedEvent` 和 `TurnResult`
- 保存/恢复存档
- 处理 API Key 的页面内存生命周期

不负责：

- 筛选种子事件
- 应用规则效果
- 判定死亡、突破或结局

### 5.4 AI

负责：

- 构造受限模型请求
- 解析模型结构化输出
- 校验叙事草稿
- 处理超时、重试、预算和后备模式
- 脱敏日志和错误

不负责：

- 修改状态
- 修改规则效果
- 决定世界线排期
- 决定结局

### 5.5 Persistence

负责：

- 定义存档读写接口
- 校验存档版本
- 迁移旧存档
- 保存插件 ID、版本和私有状态

不负责：

- 保存 API Key
- 绕过核心直接改变游戏规则

## 6. 关键设计决策

### 6.1 SeedEvent 与 RenderedEvent 分离

原因：

- 规则需要稳定、可验证、可测试。
- AI 文本需要可替换、可失败、可回退。
- 页面不能直接依赖规则内部结构。
- 存档需要区分内容来源和展示版本。

### 6.2 StandardEffect 统一状态修改

原因：

- 插件只能声明“想做什么”，不能直接做。
- 核心可以拒绝未知或越界效果。
- 效果可以序列化、审计和测试。
- 死亡、突破和结局仍保留在核心。

### 6.3 ContentRegistry 冻结注册

原因：

- 避免运行中任意增删内容导致不可复现。
- 便于检查重复 ID、命名空间和版本。
- 单个插件失败时可以隔离。
- 核心只依赖只读内容视图。

### 6.4 后备文本是一等契约

每个事件和每个选项结果都必须有后备文本，原因：

- 没有 Key 时游戏仍可玩。
- 模型超时或返回非法格式时仍可玩。
- 测试不需要真实模型。
- AI 失败不会阻断核心回合。

## 7. 待确认的核心设计问题

- 完整 `GameState` 的字段和插件新增属性映射。
- `apply_choice` 在 AI 扩写后的最终调用形态。
- 条件系统采用声明式 DSL、Python 规则钩子，还是两者组合。
- 世界线排期如何与随机种子结合以保证可复现。
- 插件新增地点、人物、行动如何进入候选筛选。
- 插件版本迁移和存档迁移的责任边界。
- AI 叙事校验由 AI 层、核心层还是共享校验模块执行。

这些事项在确认前，不应被固化为不可回退的公共契约。
