# XianWen 设计说明

- 状态：Draft v0.2
- 更新时间：2026-11-19
- 本版变更：采用核心/动态世界状态分层、受控 AI 内容生成、事件簿和隐藏伏笔系统
- 维护责任：A（核心规则）牵头，全体成员 Review
- 关联文档：`docs/接口文档.md`、`docs/契约文档.md`、`docs/prd-v1.md`、`docs/tech-design-v1.md`

## 1. 文档目的

本文档说明 XianWen 的核心架构、模块职责、数据所有权、回合数据流和阶段边界。

它回答“为什么这样设计”：

- 哪些状态是权威事实？
- AI 可以生成什么？
- 生成内容如何校验、登记和保存？
- 事件簿和伏笔如何影响后续回合？
- 哪些能力属于第一阶段，哪些属于完整 MVP？

接口和字段定义分别见 `docs/接口文档.md` 与 `docs/契约文档.md`。

## 2. 核心设计原则

### 2.1 代码是世界事实的权威

所有确定性规则必须由 Python 核心执行：

- 年份、回合和世界线推进
- 玩家数值和状态迁移
- 标准效果校验与应用
- 事件候选筛选
- 生成内容数量、引用和数值限制
- 伏笔认证和到期调度
- 死亡、突破和结局判定

AI 负责叙事和内容提案，但不拥有世界事实的最终写入权。

### 2.2 AI 可以生成内容，但不能直接改变世界

AI 目标能力包括：

- 扩写场景、选项和结果文本
- 从种子事件派生新事件
- 提出新地点和人物
- 提出新选项及受限标准效果
- 提出伏笔候选
- 为事件簿生成摘要草稿

AI 不能：

- 返回新的 `GameState`
- 修改 `CoreWorldState`
- 修改玩家状态
- 直接应用效果
- 直接写入伏笔账本
- 创建最终结局或新的主线世界线
- 读取隐藏伏笔真相用于普通叙事

所有 AI 输出都是提案，必须经过核心校验和提交。

### 2.3 核心状态和动态状态分离

`WorldSnapshot` 分为两部分：

```text
WorldSnapshot
- core: CoreWorldState       # 权威状态，只能由核心推进
- dynamic: DynamicWorldState # 可演化内容，以不可变快照提交
```

`CoreWorldState` 保存年份、回合、世界线阶段和状态版本。它并不是“永远不会变化”，而是：

> 每个回合都是不可变快照，只有核心状态迁移函数可以生成下一版。

这解决两个问题：

- 年份不会被 AI 或插件直接改写。
- 动态内容不会与核心字段形成两个事实来源。

### 2.4 所有生成内容必须持久化

AI 生成的地点、人物、事件、选项和效果必须在当前局登记。

临时叙事细节可以只存在文本中，例如：

- 一阵风
- 一个无名路人
- 远处的钟声

但持久化实体必须进入 `GeneratedContentStore`：

- 新地点
- 新人物
- 新事件
- 新选项及效果

否则刷新页面后会丢失内容，AI 生成的因果关系也无法恢复。

### 2.5 事件簿记录事实，摘要只是表达

事件簿必须保存：

- 事件 ID
- 选择 ID
- 实际效果
- 涉及人物和地点
- 回合和年份

一到两句摘要可以由 AI 润色，但不能改写已发生的事实。AI 失败时必须使用核心生成的固定摘要。

### 2.6 伏笔必须由核心调度

伏笔不是普通叙事文本，而是有来源、评分、状态和期限的世界事实。

认证流程：

```text
AI 提案
→ 确定性校验
→ 第二个评审 agent 评分
→ 超过阈值
→ 核心认证
→ 写入隐藏 ForeshadowBook
→ 十回合内由核心调度响应
```

两个 AI 角色不能直接决定世界事实。它们只能提供候选和评分，认证与写入由核心完成。

## 3. 完整回合数据流

### 3.1 开始时

```text
1. 浏览器恢复已提交 GameState
2. 核心生成公开世界投影
3. 核心从种子和生成事件中筛选 2-3 个候选
4. 核心标记即将到期伏笔和可用回收事件
```

### 3.2 AI 生成阶段

```text
5. AI 生成 NarrativeDraft
6. AI 可选生成 ContentGenerationDraft
7. AI 可对候选伏笔提出 ForeshadowProposal
8. 核心校验叙事、内容和效果预算
9. 核心分配正式 ID 并登记生成内容
10. 核心生成 RenderedEvent；失败时使用种子后备文本
```

### 3.3 玩家选择后

```text
11. 玩家选择固定 choice_id
12. 核心从种子或生成事件解析 StandardEffect
13. 核心应用效果并生成新的 WorldSnapshot
14. 核心写入 ChronicleEntry 和人物记忆引用
15. AI 可生成摘要草稿；失败时使用核心模板摘要
16. 第二个评审 agent 对伏笔候选评分
17. 核心认证合格伏笔并写入隐藏账本
18. 核心检查到期伏笔并保证响应
19. 核心推进年份和世界线，保存新状态
```

关键点：

- AI 文本不能成为规则依据。
- AI 生成内容必须先登记再使用。
- 事件簿写入发生在实际效果应用之后。
- 伏笔响应由核心调度，不由 AI 自行决定。
- 年份和世界线只在核心提交阶段推进。

## 4. 阶段边界

### 4.1 第一阶段最小回合已实现

当前最小垂直切片：

```text
new_game
→ get_current_event
→ apply_choice
→ TurnResult
```

包含：

- 最小 `GameState`
- 固定事件 `base.morning_training`
- 两个固定选项
- 固定结果文本
- 核心异常和单元测试

### 4.2 世界状态分层骨架已实现

新增 `src/xianwen/core/world_state.py`，包含：

- `CoreWorldState`
- `DynamicWorldState`
- `WorldSnapshot`
- `StateTransition`
- `StandardEffect` 基础审计载体
- 状态版本冲突和非法迁移异常

关键行为：

- 所有状态对象均为不可变快照。
- 普通提交必须携带 `expected_version`。
- 状态版本每次提交精确增加 1。
- 回合、年份和状态版本由核心迁移函数推进。
- 普通迁移不能修改随机种子、内容版本或世界线 ID。
- 世界线切换必须等待专用迁移接口。
- 已新增 `PlayerState`、`ChronicleEntry`、`ForeshadowBook` 数据模型。
- 新 `GameState` 已对齐 PRD，由 `PlayerState`、`WorldSnapshot`、事件簿和伏笔账本组成。
- 旧状态已重命名为 `LegacyGameState`，由 `new_game()` / `apply_choice()` 继续兼容。
- `StateTransition` 和状态迁移函数只属于核心内部；插件只能提交 `StandardEffect` 提案。
- `PlayerState` 与 `WorldSnapshot` 必须在同一个 `GameState` 原子提交中更新，不能分两次落账。
- `PlayerState.items` 表示玩家背包，`DynamicWorldState.items` 表示世界物品；同一物品不得重复归属。
- 新种子回合最小原子结算入口 `apply_seed_choice()` 已实现。
- 当前仅支持 `cultivation_delta`，未知效果失败关闭。
- 已新增受控内容生成草案：地点、人物、事件、选项和效果。
- 已新增 ContentGenerationPolicy 和 EffectBound，用于后续确定性校验。
- 草案尚未进入状态，正式 ID、引用校验和 GeneratedContentStore 登记尚未实现。

当前仍未包含：

- AI
- 种子筛选、候选选择和更多效果类型（最小原子回合结算已实现）
- 生成内容校验
- 事件簿
- 伏笔
- 插件加载器
- 完整回合流程与 AI 叙事接入（计划由 `feat/seed-contract` 实现）
- 插件专用公开 API 与状态提交入口隔离（计划由 `feat/plugin-contract` 实现）

### 4.3 完整 MVP 目标

- 10 回合流程
- 2 个结局、2 条世界线
- `CoreWorldState` + `DynamicWorldState`
- `SeedEvent` + `SeedChoice`
- `NarrativeDraft` + `ContentGenerationDraft`
- AI 生成地点、人物、事件和选项
- 统一 `StandardEffect` 和 `ContentGenerationPolicy`
- 事件簿和人物记忆
- 伏笔提案、评分、认证、十回合响应
- 插件和 AI 生成内容共用契约
- 固定后备模式

### 4.4 当前代码的迁移方向

```text
第一阶段兼容接口：LegacyGameState + Event + apply_choice   # 继续可运行
新 GameState：PlayerState + WorldSnapshot + chronicle + foreshadows  # 已对齐
世界状态新骨架：WorldSnapshot + StateTransition      # 已并行实现
→ SeedEvent + SeedChoice
→ RenderedEvent
→ GeneratedContentStore
→ ChronicleEntry
→ ForeshadowBook
```

迁移过程中必须保持第一阶段最小回合可运行，不能一次性替换所有接口。新的世界状态层不得直接改写旧 `GameState`，旧接口也不得绕过状态版本提交规则修改 `WorldSnapshot`。

## 5. 模块职责

### 5.1 Core

负责：

- `CoreWorldState` 和 `DynamicWorldState` 迁移
- 候选种子筛选
- 标准效果校验和应用
- 生成内容校验与正式 ID 分配
- 事件簿写入
- 伏笔认证和到期调度
- 死亡、突破和结局判定
- 生成公开世界投影

不负责：

- HTTP 和模板
- 模型请求
- 插件目录扫描
- 直接读取隐藏伏笔并将其暴露给普通叙事

### 5.2 Plugins

负责：

- 扫描插件包
- 校验清单、内容和版本
- 向 `ContentRegistry` 注册内容
- 提供种子、地点、人物、行动、结局和可选规则
- 隔离加载与运行错误
- 管理插件命名空间和私有状态

不负责：

- 修改 `CoreWorldState`
- 直接修改玩家状态
- 决定核心回合顺序
- 修改基础规则和基础结局

### 5.3 AI

负责：

- 生成叙事草稿
- 生成受控内容提案
- 提出伏笔候选
- 对伏笔进行结构化评分
- 生成事件摘要草稿
- 处理超时、重试、预算和后备模式
- 脱敏日志和错误

不负责：

- 提交状态
- 应用效果
- 认证伏笔
- 推进年份和世界线
- 普通叙事读取隐藏伏笔真相

### 5.4 Web

负责：

- 开始页、游戏页和结局页
- 提交选择
- 展示 `RenderedEvent` 和 `TurnResult`
- 展示公开事件簿和人物志
- 保存/恢复存档
- 管理页面内存中的 API Key

不负责：

- 筛选种子
- 应用效果
- 生成或认证伏笔
- 展示隐藏伏笔真相

### 5.5 Persistence

负责：

- 保存和恢复 `GameState`
- 保存生成内容、事件簿、人物记忆和伏笔账本
- 保存插件 ID、版本和私有状态
- 校验存档版本并执行迁移
- 保存模型用量，但不保存 API Key

## 6. 关键设计决策

### 6.1 SeedEvent 与生成内容分离

`SeedEvent` 是稳定规则和剧情骨架；AI 生成内容是当前局的世界扩展。

- 基础/插件种子是发布内容。
- AI 生成内容属于当前存档。
- 两者都使用相同字段契约和效果白名单。
- 生成内容必须带来源种子和生成版本。

### 6.2 ContentGenerationDraft 与 ValidatedGeneratedContent 分离

AI 输出只是不可信提案：

```text
ContentGenerationDraft
→ 确定性校验
→ ValidatedGeneratedContent
→ 核心分配 ID
→ commit_generated_content
```

这样 AI 不能直接用临时 ID 或越界效果写入世界。

### 6.3 事件簿与伏笔账本分离

- `ChronicleEntry`：玩家可见或可查询的事件历史和摘要。
- `ForeshadowRecord`：玩家不可见的未来因果承诺。
- `WorldFactRecord`：核心认证的永久世界事实。

不要把伏笔直接塞进事件簿摘要，否则会泄露给玩家或失去到期调度能力。

### 6.4 伏笔评审只是过滤器

多 agent 评分可以过滤低质量和世界观不一致的伏笔，但不能替代核心校验。

必须同时满足：

- 确定性引用和规则校验
- 世界观一致性最低分
- 未来回收可行性最低分
- 总分超过阈值
- 活跃伏笔数量未超限
- 到期回合合法

### 6.5 后备文本是一等契约

所有种子事件和选项必须有后备文本，原因：

- 没有 Key 时游戏仍可玩。
- 模型超时或格式错误时不中断。
- 测试不依赖真实模型。
- AI 生成内容失败时不污染世界状态。

## 7. 失败与回退策略

### 7.1 AI 叙事失败

```text
NarrativeDraft 非法或超时
→ 重试一次
→ 仍失败则使用 SeedEvent 后备文本
```

### 7.2 AI 内容生成失败

```text
ContentGenerationDraft 非法、引用不存在或超限
→ 拒绝整份内容提案
→ 不登记任何新地点、人物或事件
→ 使用原有种子事件继续回合
```

不能只接受提案的一半，避免出现半成品世界状态。

### 7.3 伏笔失败

```text
ForeshadowProposal 校验失败或评分不足
→ 不认证
→ 不写入 ForeshadowBook
→ 不影响当前回合
```

### 7.4 伏笔到期失败

```text
到期伏笔没有合适回收事件
→ 核心选择后备回收事件
→ 无法回收则产生明确升级、代价或过期后果
```

不能静默删除。

### 7.5 插件失败

```text
单个插件加载或运行失败
→ 只禁用该插件
→ 基础内容和其它插件继续运行
→ 保留历史私有状态用于再次启用
```

## 8. 安全与私密状态

- API Key 只存在页面内存和单次服务端请求中。
- 普通叙事生成只接收 `PublicWorldProjection`。
- 隐藏伏笔真相只提供给核心授权的回收事件生成。
- AI 输出不得写入 HTML；模板必须自动转义。
- 插件和 AI 生成内容不得访问其他插件或用户秘密。
- 所有外部输入和模型输出必须经过结构化校验。
- 日志不得记录 Key、完整模型请求或隐藏伏笔真相。

## 9. 待确认事项

- `PlayerState`、`DynamicWorldState` 的最终字段。
- `Condition` 与 `StateRequirement` 的声明式格式。
- 生成内容提交与事件簿写入是否同一事务。
- 伏笔评分 rubric、阈值和过期回收模板。
- 生成内容的数量、数值和存档规模上限。
- AI 生成内容与插件内容的 ID 分配规则。
- `apply_choice` 在生成事件、事件簿和伏笔接入后的最终签名。

## 10. 变更规则

- 新增或修改核心回合流程、模块职责、依赖方向或关键设计决策：必须更新本文档。
- 新增或修改公开接口：必须同步更新 `docs/接口文档.md`。
- 新增或修改数据结构、效果、插件、AI、事件簿、伏笔或存档契约：必须同步更新 `docs/契约文档.md`。
- 同时影响接口和数据的改动必须同时更新两份文档。
- 未同步文档的接口、契约或核心设计改动不得合并。
